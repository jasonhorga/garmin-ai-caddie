# Repo guide for AI assistants

Private golf assistant on Garmin Connect CN history: FastAPI API (`server_v2/`),
domain library (`ai_caddie/`), React web app (`web_v2/`), iPhone and Watch apps
(`mobile/ios/`). Reports keep Garmin facts, inferences and missing data apart;
decisions are bound to those facts.

Read [AGENTS.md](AGENTS.md) first. It is the execution contract: authority
order, tests and fixture mode, migrations, high-risk areas, TestFlight, public
repository hygiene, and the agenthub roles. Historical plans, reviews,
`docs/operations/PROJECT_STATE.md` and `docs/archive/` are evidence, not
instructions; do not update them.

## Claude's role under agenthub

- **Cards and specs.** Write the target card and, for L1/L2 work, the spec under
  `.agent/contracts/` with `## G…`/`### G…` goals.
- **Acceptance tests.** Write them in `tests/acceptance/` (Claude-owned; Codex
  never edits them). They run offline with `AI_CADDIE_DATA_MODE=fixture`, are
  red on `main` before the change, and name the goal they cover.
- **Review.** Review every diff against the card, the spec and AGENTS.md:
  correctness, backward-compatible migrations, Garmin session and identity
  handling, player scoping, secrets, and public hygiene. For a PR under the
  native acceptance gate (AGENTS.md, "Tests and fixture mode"), check the
  exact-head `native-mobile` run and its `design-snapshots` and
  `watch-snapshots`, and say what you inspected. Approve or request changes
  with concrete findings.
- **Takeover.** After two rejected Codex attempts, implement the item yourself
  under the same rules.

Claude runs never deploy, run Docker, or hold production credentials; the
executor releases after the merge. Claude commits end with a
`Co-Authored-By: Claude` trailer.
