# garmin-ai-caddie 产品测试规格 v3 定稿（2026-10-23，卡 C16）

依据：main 762b3f44 的产品文档（README 2026-09-25 重设计 + IMPLEMENTATION_PLAN/B4b-2、成绩合并设计、USER_GUIDE/产品手册中仍被沿用的部分、RUNBOOK §4）。不参考现有 tests/。手表以 D02 为准；九洞按两个半场，不合成"全场"。产品分歧 Jason 10-23 已定（见文末）。

**写法**：每条 = 他做一件事 → 产品承诺 → 坏了他会遇到什么。一条一个主测试，球场/顺序/状态是数据行。**判据规则**（全文适用）：
- 期望值手写在题面 fixture 里（小球场、少几场、手算表），不用被测函数生成；"A 与 B 一致"类承诺必须同时断言独立 golden，否则两边一起错也会绿。
- "三方案真不同" = 手写 golden 里三方案的落点序列或杆序至少一处不同，且各自等于 golden。
- 不测文案、源码/配置文本、像素；视觉承诺只测布局边界（frame 不相交、在可视区内）；"页面照常" = 关键视图在、无错误态。
- 秘密/隐私检查：运行时注入秘密样本，查实际响应、日志、存储、模型输入，不搜源码。
- 协议细节（键名、状态码、文件格式）不是承诺，归附录"实现契约"，由数据行间接覆盖。
- 标 **现品必红** 的是已核实的产品 bug（C20）：先写红、修复后验收。

层：U Python 纯函数 · I 后端 HTTP+DB · S Swift 单元（各测试 target 真跑）· W Web Playwright（web_v2，fixture 后端）· V iOS/Watch UI/快照（fixture 后端）· A 跨层验收（项目台写）。

## 发布门（不在套件内；全部观察运行结果/容器状态/HTTP，不读配置文本）
- G1 本地与公网 `/health` 的 revision = 刚上线 SHA。

- G3 RUNBOOK §4 核对（exit 0 + `result=ok` 末行、只一个 release 容器、sync 镜像 revision = SHA、下一个 :37 sync 完成无新失败）。
- G4 无同 revision sync 镜像时 sync 拒跑并告警，告警去重、恢复只报一次。
- G5 部署失败自动恢复：health / 闸门 / sync 合约 / 公网 health 各自失败一遍，每遍都断言旧容器仍健康、对外服务不中断、数据卷未换；库不健康拒绝 deploy/rollback。
- G6 发布容器不自启、端口只绑 127.0.0.1、日志有上限（`docker inspect` 实测）。
- G7 TestFlight 凭证：revision 匹配 → 允许上传；不匹配/缺失/格式坏 → 拒绝，且拒绝发生在任何上传副作用之前。
