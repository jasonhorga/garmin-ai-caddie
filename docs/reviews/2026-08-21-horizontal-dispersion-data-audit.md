# 历史击球横向散布数据审计

**日期：** 2026-08-21  
**审计对象：** homeserver 生产数据卷（候选 API/sync revision `6a6080c6f6867513ed461d20e98a29113bd65433`）  
**目的：** 判断 D07 是否可以诚实地为球童显示横向散布，而不是因为有 GPS 就画一个没有依据的椭圆。

## 结论

数据层面已经足够支持一个“历史落点云”，也足够支持一部分**目标相对的结果走廊**。但原始 Garmin AutoShot 没有记录用户当时的瞄准线/意图，因此当前不能把结果云称为“瞄准散布”，也不能在所有球杆和所有场景画一个默认椭圆。

当前建议仍是 **D07 = NEXT**，不是立即实现：先补一个带 provenance 的目标定义和最小 UI，再实现条件显示。

## 关键缺口

原始 shot 对象没有以下字段：

```text
target / aim / aimPoint / targetLoc / direction / dispersion / scatter
```

这意味着：

- `start -> pinPosition` 可以作为**目标代理**，但不是用户实际瞄准线；
- 对攻果岭的 `APPROACH`，旗位通常是合理代理，结果走廊有产品价值；
- 对 `TEE`，球员可能瞄球道、狗腿转角或安全落点，直接用旗位会把“路线选择”误判成“横向失误”；
- `pinPosition` 目前只留在原始 hole 记录，normalized shot schema 只保留 `start/end`，所以后续实现前必须扩展契约并保留来源引用。

另一个现实限制是球杆归属：22,088 行中有 15,457 行 `clubId=0`，只有 6,631 行有可解析的真实球杆。没有球杆的行仍可进入总体现实落点云，但不能进入“某一支杆的散布”。

## 目标代理的可行性试算

仅对 `TEE`/`APPROACH`，用 `start -> pinPosition` 做临时目标代理，计算终点相对于该线的有符号横向误差：

| 类型 | 可用行 | 横向 P10 | 中位数 | 横向 P90 | 绝对误差 P90 |
|---|---:|---:|---:|---:|---:|
| TEE | 5,506 | -49.2m | -0.6m | 59.5m | 71.7m |
| APPROACH | 7,140 | -22.0m | 0.0m | 20.9m | 29.1m |

这证明坐标和旗位可用于计算结果，但也证明 tee 线不能直接当作“瞄准线”：有 937 行终点超过旗位目标距离 5m 以上，另有 121 行横向误差超过 100m。它们不一定是坏数据，很多是合理的开球路线、layup 或偏离球道后的下一杆。

按真实球杆分组时，Driver 的 `TEE` 样本约 3,045 行；`APPROACH` 中 6I、7I、3W、3H、54、58 等多支杆达到 20 行以上。样本足够的组可以做统计，但必须把无球杆行排除出杆级模型。

## 推荐的实现边界

### V1：历史落点云（可以做）

- 只画实际 `endLoc`，标题写“你的历史落点”；
- 只显示当前用户自己的数据；
- 不画椭圆，不写“瞄准误差”；
- 按 `shotType` 和真实球杆筛选；样本不足时显示空状态和样本数；
- 继续复用现有 `yourShots` 投影和 `shot_projection.py`，不改变坐标权威。

### V1.1：条件目标走廊（需要先补契约）

只在以下条件同时满足时显示：

1. 目标类型明确：`flag`（攻果岭）或 `route/fairway`（开球），不能把两者混写；
2. 每杆/类型至少 30 个有效样本；
3. 目标、坐标转换、几何 revision 都有 provenance；
4. 目标与击球属于同一洞/同一九洞映射，9+9 合并不能丢 target 关系；
5. 没有实时风、球位或击球意图时，文案明确是“历史结果范围”，不是成功率预测。

建议新增的最小数据形状：

```json
{
  "target": {
    "kind": "flag|route_proxy",
    "source": "garmin_pin_position|course_geometry",
    "sourceRef": "...",
    "geometryRevision": "..."
  },
  "lateralM": 12.4,
  "longitudinalM": -6.1,
  "sampleQuality": {"n": 84, "excluded": 3, "confidence": "medium"}
}
```

### 暂不做

- 不从 `start -> pin` 推断 tee 的真实瞄准线；
- 不把跨球场混合结果显示成当前洞的精确命中概率；
- 不在没有 geometry/target provenance 时绘制合成椭圆；
- 不把 `clubId=0` 的行强行归入某支杆。

## 对旧 Plan 4 D07 的裁决

D07 的用户价值成立，现有数据也足以开始一个小范围实验；但“二维散布模型仓库、lie-conditioned model repo、随机规划器”等平台化任务仍然过度。正确的下一步是一个小的、可回滚的结果云/走廊契约，加上真实设备视觉验收；不是重启旧 Plan 4 的整棵任务树。
