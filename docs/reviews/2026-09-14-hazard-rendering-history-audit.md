# 障碍物轮廓与“旧版本”逻辑审计

日期：2026-09-14  
审计范围：仓库 Git 历史、当前 iPhone/Watch 渲染代码、CourseView/PRODGeometry 障碍数据链路，以及 PHONE-UX5 发布证据。

## 结论

“旧版本”不是当前应用里一个神秘的运行模式。之前的说法不准确，实际上混用了三件事：

1. Git 历史中确实存在过的渲染代码；
2. 已发布但被后续 Build 取代的 TestFlight 二进制；
3. 为了读取已有下载包而保留的区间数据兼容路径。

这次截图对应的 iPhone 椭圆选中框只有一段：`04adc25c` 中的
`LiveHazardFocusRingLayout.rect` + `Path(ellipseIn:)`。它在
`74423bd2` 被删除。早期 Watch 原型也曾有独立的椭圆高亮，已由
`cda8cfdc` 改成真实地图上的点标注。当前 Build 61 的源码不包含任何障碍形状椭圆兜底。

后端的真实轮廓链路早于上述 iPhone UI 修复就已存在：
`_component_boundary_edges` 从三角网格中保留只出现一次的外部边，
`_component_outline` 排序成闭合边界，`_hazard_detail` 投影为 `outlinePx`。
因此“详情数据没有 `outlinePx`”不等于“底图没有沙坑形状”。

## 当前实际运行规则

- 有 `outlinePx`（至少三个合法点）：在固定像素标注层沿真实不规则边界画细红线。
- 只有 CourseView 的前/后沿区间：底图仍可显示 CourseView 的事实地图；界面只显示前/后沿事实，不伪造轮廓。
- 既没有网格也没有边界点：不能推断形状，不画椭圆、不画圆圈。
- 已下载的旧包仍可被解码，是为了不让离线或缓存数据崩溃；它不是“旧 UI”。当前代码会在 ready 包缺少真实轮廓时请求精确 prep，并且不会用不完整响应覆盖已有可用地图。

## 为什么 Git 里还看得到旧逻辑

Git 提交和发布证据是审计记录，不能把已经发生过的代码从历史中抹掉来伪造时间线。它们不会进入当前构建。当前代码里保留的只是数据协议兼容（区间数组和可选 `outlinePx` 解码），不是椭圆渲染算法。

本次审计同时把当前源码中的 `legacy` 视觉命名改成了“interval/compatibility”语义，并把焦点布局重命名为 `LiveHazardAnnotationLayout`，避免再把兼容数据误称为一个“旧版本 UI”。
