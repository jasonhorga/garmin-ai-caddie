## 2. 已核证 S70 Experience DNA 的重新提炼

### 2.1 七条 DNA（全部重新落在证据包坐标上）

1. **单一当前洞 + 浅仪表面**。球局中永远只有一个「家」（洞主屏）；Golf Menu 的 14 项能力（View Green/Virtual Caddie/Change Hole/Scorecard/PinPointer/Measure Shot/End Round…）是围绕当前洞切换的「面」，Back 永远回洞主屏（证据包 §1.6）。不存在兄弟页心智。
2. **距离是背景辐射，不是目的地**。默认洞主屏 = 顶部洞号/Par + 左侧 F/M/B（中距最大、黄色）+ 右侧彩色洞图 + 顶部上一杆距离（§1.3 OFFICIAL）。看距离没有「导航」这个动作。
3. **场地推进状态，人只做确认**。开局若离某洞最远后 tee ≤30 m 即可从该洞开始（§1.2）；走近下一洞最远后 tee 自动换洞（§1.10）；洞末提示录分且默认预填 Par（§1.9）。用户输入几乎全部是「对预测的确认或微调」。
4. **检测静默入账 + 一次轻确认**（上一轮此条已修正）。AutoShot 不打断挥杆，检测后只在顶部更新上一杆距离；开启 Club Tracking 时检测成功会弹一次 Club Prompt——它同时是球杆输入和「本杆已识别」的隐性成功信号（§1.8 OFFICIAL/MULTI-SOURCE）。S70 不是「场中永远零输入」，而是「一次点击换取双重价值」。
5. **等待前置，场中零 loading**。GPS 数秒锁定、地图离线预装；但风/空气密度依赖手机且会静默陈旧（§1.2/§1.4）——前半条是 DNA，后半条是必须修正的缺陷。
6. **触屏做空间事，按键做流程事**。点地图放 target、拖旗在放大果岭上；Action/Menu/Back 三实体键承担开局、菜单、返回（§1.1/§1.5）。空间输入与流程输入分通道。
7. **收口有仪式，但没有守卫**。`Action → End Round → 统计 → Save/Edit/Discard/Pause`（§1.12）是明确仪式；但没有可靠的 9/18 洞自动收口，忘记结束会把回家 27 英里计入球局——仪式存在、守卫缺位，是要「还原仪式 + 补上守卫」的地方。

### 2.2 上一轮结论的保留与撤销

**撤销（对应证据包七项修正，逐条认账）：**

| 3 | PlaysLike 并列常显（§4.5/§7-C5） | 点距离切换 + 上滑看分量 | 仓库现有 toggle 行为**是 S70-faithful 的**；C5 指控撤销 |

## 3. 白纸推导：核心任务循环与完整 18 洞状态机

### 3.1 任务物理学（不看任何旧 IA）

一轮 18 洞 ≈ 4 小时。腕上产品的任务频谱（次/轮）：抬腕看距 30–60+；击球 70–100（其中推杆 25–36）；可记录的非推杆击球 40–70；洞末计分 18；地图目标/障碍/果岭查询 3–15（前几轮多、熟场后少）；菜单动作 2–5；开局/结束各 1。两条物理约束决定一切：**看距离的预算是「抬腕即得」，不允许任何导航**；**每一次强制输入都在和球伴聊天、拎包走路、戴手套抢时间**。

### 3.2 完整 18 洞状态机（本报告三方向共用的骨架；方向差异在 §4 标注）

```
【球局生命周期】
idle ──开始──▶ starting ──就绪──▶ active(hole=h) ──暂停──▶ paused ──恢复──▶ active
                                        │
                                        ├─结束仪式─▶ finishing ─确认─▶ finishedPendingSync ─全部ACK─▶ synced(留存历史)
                                        │                    └─继续打─▶ active
                                        └─放弃(双确认)─▶ discarded(唯一删除路径)

【starting 开局】
打开 app / 复杂功能 ─▶ 有 active/paused 局? ──是──▶ 「继续 · 第h洞」/「结束旧局」二选一(绝不静默弃)
                                    └─否─▶ 选场(手机包就绪则直入;否则就近列表)
                                           ─▶ 9/18+发球台 ─▶ 记分/统计开关(记忆上次)
                                           ─▶ GPS 并行搜星 ─▶ 起始洞 = 就近 tee(≤30m 判定,默认1号) ─▶ 洞面

【active 内:洞面 = 唯一常驻屏,五类仪表面围绕它】
洞面(hole=h) ── 触/冠 ─▶ {全图态 / 障碍停点 / 果岭特写(拖旗) / 洞况(实打分量) / 球童详情}
    │                    全部 Back/下滑 ─▶ 洞面
    ├── 记杆(常驻入口) ─▶ 先持久化{fix,ts,hole,shotId} ─▶ 球杆层(确认/未知/撤销) ─▶ 洞面
    ├── 计分(chip/菜单) ─▶ 计分面(总杆·推杆·[球道]·罚杆,原子保存) ─▶ 洞面(不跳洞)
    └── 菜单(固定角标) ─▶ {计分卡/选洞/旗向/大字模式/球杆确认队列/设置/暂停/结束}

【换洞:置信阶梯(location-driven,与计分完全解耦)】
GPS 候选洞引擎: 输入 = fix(acc,age) × 各洞 tee/green 坐标 × 驻留 × 滞回
  高置信(acc≤A₁,驻留≥T₁,距下一洞tee≤R₁ 且远离本洞果岭≥R₂)
      ─▶ 自动换洞 + 触觉tick + 全屏宣告「第h+1洞 · Par4」+ 10s 内可一键撤销
  中置信 ─▶ 洞面浮出「换到第h+1洞?」小签,点确认,不点不动
  低置信/无fix/无坐标 ─▶ 只保手动(菜单·选洞);洞面显示 GPS 质量标
  换洞后上洞未记分 ─▶ 新洞面浮「记第h洞?」小签(不弹窗、不阻塞)
  误换 ─▶ 撤销钮 / 选洞;换洞事件(from,to,origin)全部入账本可回溯

【记杆↔计分对账(贯穿全轮)】
逐杆账本(B级证据) ⇄ 洞末确认总杆(A级事实)
  计分面预填: 有账本→已记杆数;无→Par(S70 默认)
  来源行:「已记 N 杆」;确认值≠N → 记 strokesUnaccounted,不阻塞保存
  未知球杆 → 洞末批量确认条(冠滚+点),跳过=保持unknown,不进球杆统计

【结束与守卫(主动超越,非还原)】
第18洞(或选定洞数)已记分 ─▶ 浮出结束建议(可收起)
守卫: 连续X分钟无移动向任何洞 且 远离全部洞几何 ─▶ 通知「还在打吗?暂停/结束」
      绝不自动 discard;守卫只产生建议与自动 paused(有通知),不产生数据变更

【同步】
事件产生即入单一 WAL/outbox ─▶ 主通道=手机中继 / 备通道=直连(仅手机不可达且配置有效)
逐事件ACK;结束→finishedPendingSync(数据完整保留)→重试→synced→留存最近N轮历史
无配置/无网: 一切照常,开始页与菜单如实显示「待同步N·未配置」——不再承诺做不到的事

【恢复矩阵】
杀进程/重启 ─▶ 恢复到当前洞洞面(账本/草稿/outbox 零丢失)
垂腕→抬腕(会话存活) ─▶ 原样恢复;空闲>T₃ 或洞已变 ─▶ 折回洞面
GPS 陈旧 ─▶ 距离变灰+时效标;>T₄ ─▶ 长划线,绝不显示错数字
错洞 ─▶ 洞面常驻「GPS 认为你在第k洞」差异标(当k≠h)→点即切
漏杆 ─▶ 任意时刻「补记一杆」(位置可空/可图上指,位置空者不进距离统计)
误杆 ─▶ 击球列表删除/改杆(append 纠正,不物理删)
忘记结束 ─▶ 守卫;动态数据(风) ─▶ 只在新鲜度合格时出现,过期即标注或消失
```

阶梯参数 A₁/T₁/R₁/R₂/T₃/T₄ 全部是真机标定项（§9），设计只锁**结构**：自动性随置信度递减、每次自动转移可见可撤销、计分永不成为换洞的门。

## 4. 三个概念方向

三方向共享 §3.2 骨架与 §6 裁决表，分歧在**最深的一根轴**上：

- **方向 A「被动测距仪」**：真相记录 = 洞末确认的成绩；逐杆是可选证据。仪器为「看」服务。
- **方向 B「逐杆账本仪」**：真相记录 = 每一杆；成绩由账本推导、洞末只确认。仪器为「记」服务。
- **方向 C「watchOS 原生页阵」**：不与系统习惯搏斗；表冠=导航，页=功能，自动换洞取消。

### 4.1 方向 A「被动测距仪」（S70 体感的正统翻译）

**根 IA 与主洞屏**：唯一根 = 洞面。版式忠实于官方主屏（§1.3）：顶行「第7洞 · Par4」+ 上一杆药丸；左列 38% F/M/B（中距最大、金黄、21→28pt 按表径缩放）；右侧 topo 洞图（球童线 + layup 点 + 旗）；左列底部一行球童建议「7铁 · 打前沿」（点开进球童详情面）。**2026-07-15 证据更正**：本段原先把 18 洞成绩环列为“默认首帧不出现”，依据的“S70 没有该环”事实错误。Garmin 官方 `Score History` 证明 S70 使用物理 1–18 洞刻度 + 屏内逐洞成绩色段，因此撤回“迁至计分卡面”和“申请推翻 owner KEEP”的建议；默认应保留在 Hole Root，具体矩形几何与交互态隐藏时机再做原型。默认首帧仍不应出现：同步状态、未校准期望杆数、固定散布椭圆。完整证据见 [S70 成绩环证据更正](2026-07-15-s70-score-history-ring-evidence-correction.md)。

**Action/Back 等价翻译**：Action 的三个语义拆开承接——「开始打球」= app 打开/复杂功能直入开局；「球局菜单」= 洞面右下角**固定带字角标「菜单」**（全轮同位，肌肉记忆等价物）；「Ultra Action 键」= 一键记杆（唯一可拥有的硬件按压）。Back = 系统左缘右滑（推入面）+ 下滑（浮层），**自绘返回钮清零**（现 `WatchRoundContainerView.swift:197-210` 淘汰）。

| 结束建议/守卫通知 | 系统通知触觉 | 每类每轮最多 1 次 |
| 击球时间窗 | **永不主动触觉** | 位置门控的提示只在行走段发出 |

**一键记杆与升级路径**：洞面右下（菜单角标上方）常驻「记杆」小角标（带字）；点按 → **先写入 shot 事件{fix,acc,ts,hole,shotId,origin:manual}并落盘，再给成功 tick**，球杆半层升起（冠滚、推荐居中标注）：点=确认球杆；下滑=保持 unknown（洞末批量确认）；层内「撤销」=删除误报（append 纠正）。升级路径：AutoShot 检测器（workout+IMU+GPS）只是同一管线的第二个 producer（origin:auto,confidence），复用同一半层/上一杆药丸/未知队列；手动钮永不撤（漏检兜底=S70 Add Shot 的无位置枷锁版）。检测成功反馈 = 上一杆药丸刷新 + 轻 tick，**不弹窗**；Club Prompt 翻译为半层自动升起但 8 秒无操作自动收起且不写任何值。

**计分链（S70 官方链忠实复制 + 对账超越）**：计分面一屏完成：总杆（冠）→ 推杆（加减片，min0）→ 球道 L/C/R（仅 Par4/5，有开球落点时 GPS 预默认，可改）→ 罚杆。预填=已记杆数或 Par；来源行「已记 N 杆」；确认≠N 记差额不阻塞。推杆语义跨端写死：**总杆含推杆，推杆仅统计**（S70 §1.9；当前无 spec 写这条，本文即第一处书面定义）。保存=原子 holeScore 事件（淘汰现三事件拼装，`WatchRoundModel.swift:192-200`）。保存**不换洞**；换洞是 §3.2 阶梯的事。补错：计分卡任意洞随时改（S70-faithful）。

**异常恢复**：全套 §3.2 恢复矩阵。方向 A 特有：因为逐杆是可选的，漏杆的最坏后果=丢证据不丢成绩；错洞差异标（「GPS 认为你在第k洞」）是常驻被动元素。

**42/45/49mm**：分三档 token：41/42mm——左列压缩至 34%、中距 24pt、菜单/记杆角标只保字不保图标、障碍停点药丸单行；45/46mm——基准（现快照 198pt≈46mm，`WatchDesignSnapshotTests.swift:29`）；49mm Ultra——Action 键=记杆、外圈留 flat bezel 边距、AOD 中距再放大。每档进入快照矩阵（现仅 46mm 一档，尺寸适配零验证）。

**优点**：与已核证 S70 体感同构度三方向最高；看距离零导航、输入全是确认式；对不记逐杆的真实用户（只想要测距仪的人）完整可用；工程上直接坐在现有分栏渲染、topo 管线、store 原子写之上。
**缺点**：逐杆数据只能靠自愿，个人球杆模型的数据增速最慢；置信阶梯是全新工程（geofence/滞回/驻留标定）；沿洞轴的可发现性弱于显式按钮。
**工程代价**：中-高。新建=coordinator 生命周期、shot/holeScore/holeAdvance 事件与契约、阶梯引擎、workout 会话、AOD 面、果岭特写、旗向面、历史留存、单一 outbox 合并；修改=地图手势层（真表冠/反投影测距/拖旗迁移）、计分面、菜单扩容；沿用=渲染底座全部。
**最大失败模式**：阶梯误换洞频率压不到「每轮≤1 次」以下 → 用户关掉自动换洞 → 退化为手动换洞的普通 app，且错洞陈旧距离的原病复发。次级失败：记杆静默入口无人用 → 差异化数据断粮（这是产品级而非体验级失败）。

### 4.2 方向 B「逐杆账本仪」（把差异化押在每一杆上）

**根 IA 与主洞屏**：同一洞面版式，但**底部通栏是巨大的「记杆」条**（左列与地图为它上移让位），球童行退为点开；洞面上滑=本洞击球列表（第1杆 240码·1木 / 第2杆 …），而不是洞况面。信息主角从「到果岭还有多远」偏移为「这洞我记到哪了」。

**Action/Back**：同 A；Ultra Action 键=记杆（此方向它就是产品的心脏）。

**输入矩阵**：与 A 相同的表冠沿洞轴与地图触摸；差异——竖滑上=击球列表、下=洞况；计分面被「确认面」替代（见下）；触觉矩阵新增「连续两洞零记录」的提醒 tick（每轮最多 2 次）。AOD：洞号/Par + 中距 + **本洞已记 N 杆**。

**一键记杆与升级路径**：与 A 同管线，但 UI 契约反转：记杆是**期望行为**——洞末若 账本数=0 则确认面首先要求补录或声明「本洞不逐杆」；AutoShot 上线后此方向收益最大（强制约变成免费）。

**计分链**：洞末不是「录入」而是「对账确认」：`「第7洞:已记5杆+2推=7?」` 冠调 ±，putts 由果岭上的记杆自动归类?——**不做**（GPS 果岭尺度不可靠，证据包 §2.2 推杆伪精确警告），推杆仍手输。球道 L/C/R 由第 1 杆落点自动判定（Par4/5）。确认后 holeScore(source:derivedConfirmed)。漏记的杆在确认面直接 +1 并追加无位置 shot（账本闭合）。
**位置换洞**：同 §3.2 阶梯，但默认档更保守（中置信小签为默认，自动换洞要求用户在设置里主动升档）——因为换洞时刻同时是对账时刻，误换的代价被放大。

**异常恢复**：新增两个专属状态——「账本-成绩分叉」（strokesUnaccounted≠0 的洞在计分卡上带标，复盘可补）与「零账本洞」（明确声明比静默缺失好）。其余同 §3.2。

**42/45/49mm**：记杆通栏在 41/42mm 挤压地图至 55% 高度，是三方向中最紧的版式；Ultra 上最舒展（Action 键分流后通栏可缩小）。

**优点**：唯一让个人球杆模型/逐杆复盘/上一杆药丸从第一天就有真数据的方向；对账语义天然内建；AutoShot 到来时无缝换引擎。
**缺点**：把 S70 用户最珍视的「零负担」（AutoShot 静默,§2.1 强共识）翻译成了「每杆一次点击」——在 AutoShot 未成立时，这恰是对 S70 体感的背叛；40–70 次/轮的强制输入没有任何已证的依从率；漏记会让推导成绩**偏低**（比偏高更糟——像作弊）。
**工程代价**：高。A 的全部代价 + 确认面/分叉状态/落点判球道；且 shot 事件必须第一天就是高吞吐主路径。
**最大失败模式**：依从率崩塌（真实用户拎包就走、不点）→ 推导成绩系统性缺杆 → 洞末确认从「一次点头」变成「每洞查错」→ 计分可信度（North Star 第一不变量）被自己的核心机制摧毁。

### 4.3 方向 C「watchOS 原生页阵」（不与系统搏斗）

**根 IA 与主洞屏**：watchOS 10 竖排 TabView 三页：上=球童/洞况页、中=洞面（同 A 版式、无沿洞轴）、下=计分页。表冠=**翻页+列表滚动**（系统本分）；地图交互只剩点按测距与点障碍（无表冠停点、无表冠缩放，缩放用双击分档）。菜单=洞面角标；记杆=洞面角标+计分页大按钮。

**Action/Back**：同 A 的拆分；Back 完全交系统。

**输入矩阵**：表冠=导航与滚动；点按同 A；拖=仅果岭特写拖旗；竖滑=翻页（与滚动由系统仲裁）；横滑=无。AOD：**系统暗化当前页**——垂腕在计分页就暗在计分页（页阵无法保证暗态是距离）。触觉：仅系统页切换 + 记杆 tick + 守卫通知；无换洞触觉（因为无自动换洞）。

**一键记杆与升级路径**：同 A 的管线与半层（这一层三方向共享）；入口在两页出现。

**计分链**：同 A 的计分面，作为常驻页存在（每杆查看的距离与每洞一次的计分同级——07-13 报告 §8.2 自己反对过这一点，此处如实列为缺点）。
**位置换洞**：**取消自动换洞**，只保留中置信小签+手动（「屏幕自己永不动」的彻底版）；小签未被点击时洞不变。

**异常恢复**：同 §3.2，但错洞恢复完全依赖用户看见小签——陈旧洞面（F/M/B 指向错误果岭）成为**默认失败态**而非瞬时态。

**42/45/49mm**：每页单一职责，41/42mm 反而最从容；Ultra 无特殊收益。

**优点**：首日可发现性最好（全部系统习惯）；工程代价三方向最低（现 hub 改造量最小）；不需要阶梯引擎即可出货。
**缺点**：表冠花在导航上——被验证的 S70 结构里导航预算是**零**（§2.1-1/2）；抬腕恢复内容不可控；错洞停留时间最长；地图交互贫化后「仪器感」不再成立，产品与任何 watchOS 高尔夫 app 无差。
**工程代价**：低-中（页壳+现组件重排+共享记杆管线）。
**最大失败模式**：做完后它「没有毛病也没有理由」——用户拿它对比 S70 时四类抱怨的第 1、2 类（层级、节奏）只被温和缓解，第 3 类（自动流程）被明确放弃；产品失去本轮重设计的存在理由。

## 5. 裁决：推荐方向 A，单一架构 + 阶段边界

**推荐：方向 A「被动测距仪」作为唯一产品架构。** 不设「北极星/落地」双轨；只有一个架构、一套事件契约、按门槛解锁的三个阶段：

- **P0 可靠性脊柱（无可见 UI 变化）**：统一 coordinator 与生命周期枚举（idle/starting/active/paused/finishing/finishedPendingSync/synced/discarded）；单一 WAL/outbox（合并 `WatchRoundStore.pendingEvents` 与 `WatchSyncClient` 的 queued_events.json 两套队列）；事件契约扩容（shot/holeScore/holeAdvance/pinSet + unknown 通道）；`confirmFinish` 数据丢失路径关闭；逐事件 ACK。**出口门**：§9 V-D1/V-D6 全绿。
- **P1 仪表主体**：洞面（含沿洞轴、真表冠、反投影测距）、果岭特写、洞况面、菜单扩容、计分面（含对账行与球道）、换洞置信阶梯、AOD/workout、结束守卫、历史留存、42/45/49 三档快照。记杆入口以**安静角标**形态随 P1 出货（管线完整、不推销）。**出口门**：V-B1 误换 ≤1/18 洞、V-A1 抬腕读距达标。
- **P2 记杆表面化**：当 P1 田测中记杆自愿依从率中位数 ≥60%（V-C1 预门）时，把记杆角标升级为更醒目的入口、洞末启用账本预填与批量球杆确认（即吸收方向 B 的确认面,而非其强制约）。若依从率不过线，记杆保持安静形态，产品仍完整。
- **P3 AutoShot producer**：沿用已双评审降格的「受控验证假设」路线，检测器作为同管线第二 producer 接入，门槛由 auto-swing spec 的真机召回率决定。

**为何淘汰方向 B**：它把 S70 已核证的最强共识（「抬腕看距快 + AutoShot 静默」，证据包 §2.1）在 AutoShot 缺位期倒转成每杆一次的强制税，且失败模式直接击穿计分可信度这条宪法级不变量。它的两件真资产——逐杆事件契约与对账确认面——已被 P0/P2 原样吸收；被淘汰的只是「成绩由账本推导」这个launch 姿态。
**为何淘汰方向 C**：它对四类已确认问题只解了半类（发现性不在四类之中）；表冠预算花错位置；取消自动换洞使「错洞陈旧距离」从瞬时态变成默认态——这是对可靠性维度的倒退而非保守。它降格为验证阶段的 A/B 对照组（只做原型不做产品）。

**推荐附带的两个明确反悔点**（第二轮请攻击）：① 若 V-B1 阶梯在两轮标定后仍 >1 次误换/18 洞，方向 A 的自动档降级为默认中置信小签（即在此点上向 Codex 规则 7 靠拢一半——保留解耦、放弃默认自动）；② 若 42mm 分栏在真机上不可读（V-E1），左列改为上下叠放变体，S70 版式忠实度让位。

## 8. 对 Codex 当前判断的最强同意与最强反对

口径：以 `2026-07-13-product-design-reuse-redesign-review.md` §8（420–521 行）为「Codex 当前判断」的最佳可得载体（该文件未署名；按本轮双研究者流程它是对侧最新设计立场，若归属有误请第二轮指正），辅以 07-11 交叉审查中 Codex 侧结论。

### 最强同意（三条）

1. **「记杆必须先持久化 GPS/时间/当前洞，再显示成功」（规则 4）以及规则 8/9/10 的可靠性纪律。** 这是把 North Star「记录永不静默消失」落到交互时序上的正确写法；本报告的记杆管线原样采纳（§4.1），并加上「成功触觉只在落盘后发出」。规则 9 的「绝不显示 0 码」在现代码里已有正确雏形（`WatchDistanceHero.swift:29-33` 全 nil 渲染空），应保。
2. **结束只进 `finishedPendingSync`、不得清 round/outbox（规则 8）。** 证据在仓库里是血淋淋的：`confirmFinish` 无配置即清空（`WatchRoundModel.swift:262-265,278-282`），且被测试固化为预期行为。这是四维中可靠性维度的第一刀，P0 即修。
3. **「单一打球主页 + 浮层/推入」优于五页与 3+2，以及「任何候选未经真机验证不得写成定案」的免疫纪律（§8.1/8.3）。** 证据包把 S70 还原为「单一当前洞 + 仪表面」（§1.6）后，这个方向从「设计偏好」升格为「与被模仿对象同构」；同时它与现有 `switch model.screen` 单根结构同构、迁移成本最低（07-14 评审已证）。本报告的方向 A 与其根 IA 大体同族。

### 最强反对（三条）

1. **规则 7「保存本洞才推进洞；GPS 永远不自动跳洞」——前半句重铸了我们正要拆除的因果错误，后半句放弃了 S70 的核心 DNA。** 「保存→推进」正是 `saveActiveHole→goToNextHole` 的病根换了个方向再挂回去：它让不记分的用户（真实存在的纯测距用户）每洞手动导航，让记了分的用户被迫接受「计分=翻页」。而「永不自动跳洞」使错洞陈旧距离（F/M/B 指向错误果岭）成为**默认失败态**——用户不点小签，错就一直错；这比一次带宣告、可一键撤销、置信度门控的自动换洞危险得多。S70 官方行为（§1.10）+「手表必须在正确洞 AutoShot 才工作」这条硬约束都指向：洞状态应由场地维护、由人纠偏。我的替代方案是 §3.2 置信阶梯：**计分与换洞彻底解耦**，自动性随 GPS 置信度递减，每次自动转移可见、可撤销、入账本。若真机标定失败，我已在 §5 写明退让点——但默认立场必须是场地驱动。
2. **§8.3 的 ShotCapture/ScoreHole 两张 sheet 设计在不存在的地基上，且缺对账语义。** Codex 的 sheet 里有「删除误报/补记」，但当前契约五种 kind 没有 shot 事件、没有位置、没有 shotId（`WatchSyncClient.swift:6-12`），「删除误报」删的是什么？同时 ScoreHole sheet 只有「总杆/推杆/罚杆/保存并推进」——没有预填来源、没有「已记 N 杆」、没有 strokesUnaccounted，逐杆流与洞分确认相遇时谁赢没有答案（这正是 07-14 评审 C1，旧宪法有解而新判丢弃）。**设计顺序应当反过来：先立事件契约与对账语义，再画 sheet。** 本报告 §3.2/§4.1 给出完整对账定义供攻击。
3. **验证预算花错了地方：§8.1 要求「五页 / 3+2 / 单根」三方案各做原生原型 + 三轮真实 9/18 洞对比。** 证据包落地后，根结构问题已经被 S70 官方事实 + 工程同构性双重裁决（单根 + 仪表面），再为五页搭一个从未存在过的 TabView 壳去陪跑三轮真球，是把最贵的资源（真球场轮次）花在已经能纸面判定的问题上。真正配得上真机轮次的是四个**没有任何证据**的问题：换洞阶梯参数（V-B1）、抬腕/杀进程恢复策略（V-D2）、记杆依从率（V-C1）、AOD 烈日可读性（V-A2）。方向 C 保留为对照组即可，五页不必复活。

## 10. 供 Codex 第二轮攻击的 10 条最脆弱设计假设

1. **自动换洞（宣告+撤销）净收益为正**——我断言「错洞陈旧距离的默认态」比「偶发误换的瞬时态」更伤信任，此消彼长未经量化（V-B1/V-D3 之前纯属推理）。
2. **计分与换洞完全解耦不会造成漏记分率上升**——S70 用换洞时刻当计分提醒锚点；我把它弱化为小签，漏记率可能反升。
3. **表冠沿洞轴（全洞→障碍→果岭）比表冠缩放更值得占据根屏唯一轴**——S70 的表冠等价物（slider）是缩放；我把缩放挪去全图态/果岭面是自创，可发现性与心智负担未证。
4. **一键记杆的自愿依从率能达到 60%/80%**——整个 P2/P3 差异化路线押在这条无任何先例数据的行为假设上。
5. **无 8 秒自动写入、只靠洞末批量确认，能把未知球杆率压到 <20%**——若用户批量跳过，球杆模型断粮，等于变相回到 Codex 的 unknown 世界而多了一步仪式。
6. **42mm 上 34–38% 左列 + 右图仍然可用**——S70 的 42mm 是圆形 454 级密度屏，Apple 41/42mm 矩形更窄；「官方版式忠实」可能在最小表径上物理不成立。
7. **守卫的「远离全部洞几何」判定在只有洞级 tee/green 坐标、无球场边界多边形的数据下足够可靠**——会所紧邻球道的场地可能让守卫永不触发或频繁误报。
8. **AOD 每秒级刷新中距在 watchOS 后台刷新政策下可行**——若系统实际限频到分钟级，AOD 距离在走动中必然陈旧，设计要退回「AOD 不显示距离只显示洞号」。
9. **历史留存最近 N 轮 + 单 WAL 不会与手机中继/直连双通道产生跨通道重复或乱序**——我沿用了「中继为主、直连仅兜底」的 07-14 立场，但两通道并存的去重成本被我低估的可能性真实存在。
10. **撤下期望杆数不会降低球童建议的说服力**——S70 的 Virtual Caddie 确实展示平均杆数（证据包修正 #5）；我以「未校准」为由撤下，用户可能把「没有数字的建议」读作「没有依据的建议」。
