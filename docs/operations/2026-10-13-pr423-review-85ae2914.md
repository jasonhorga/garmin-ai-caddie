## Finding

**P2 — failed durable save can still stop the workout and lose recoverability.**

`WatchRoundModel.pauseForIdle()` calls `persistInteractionState()` and then
unconditionally clears the in-play marker, changes the screen to `.resume`,
and allows the caller to stop the workout/GPS. `persistInteractionState()`
swallows `store.save` errors with `try?` while replacing the in-memory round.
If the atomic write fails (for example, interruption, permissions, or a full
filesystem), the durable state may omit a score draft or undoable shot while
the marker is cleared and services stop. A relaunch can then see stale state,
contradicting the PR's “nothing is lost” guarantee.

Change persistence to return or throw an explicit result. Only after a
successful durable write should the marker be cleared, the screen change to
Resume, and the workout/GPS stop. On failure, keep the round active and show a
retryable error. Add a test that forces the save failure and verifies that the
stop path is not taken and interaction state remains recoverable.
