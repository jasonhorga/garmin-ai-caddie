## 2. 手机记分三屏（`score.html`）

- **本洞记分**（打完一洞弹出，也用于计分卡改历史洞）：一屏完成，不再是“推荐 → 手动确认四步”。
  - 总杆：一排可左右滑的记分符号（○ 小鸟、□ 柏忌 …），打开时从 1 杆开始排，建议值已选中，
    点哪里停哪里，不自动居中。
  - 推杆分段按钮；开球三块小球道图（Par 3 隐藏）；罚杆小 −/+。
  - **不写任何提示**（不显示“手表测到几次”“GPS 建议”等来源说明），只预选好。
  - 预选来源优先级：手表挥杆检测 → 手机“记一杆” → 默认标准杆（Par−2 上果岭 + 2 推）。
  - 开球结果由第二杆 GPS 位置对照球道轮廓预选（服务端有球道轮廓，需确认是否下发给 App，
    或由服务端算好再下发）。
- **计分卡**：大号总成绩 + 每洞累计走势线 + 前九 / 后九记分符号卡（OUT / IN）；
  选中某洞后“去这洞 / 改成绩”；“结束本场…”放在这里（新主屏没有菜单）。
- **本场汇总**：与赛后复盘同一版式（成绩 → 记分卡（点成绩看落点）→ 球道命中 / GIR / 推杆 / 罚杆四格），
  保存后直接成为复盘页。**不显示同步状态**：保存先落本地，后台上传，没网排队自动补传。
  “放弃本场”先确认并写明会删除什么。
- GIR 不单独记录，由总杆和推杆推算，汇总里标“按推杆推算”。
- 默认值保存会让统计虚高：每洞记下成绩来源（手表 / 手机 / 默认），统计推杆和 GIR 时跳过未改过的“默认”洞。

## 3. 手表（`watch.html`，以后记分主力在手表）

- **本洞**：上下滑三页（右侧小点），和手机同一 topo、同一三距离。
  1. 方案：地图画 AI 球童路线和落点（“D 224”“3W 205”）；左侧绿色球杆签 = 下一杆用杆，**点它换方案**。
  2. 障碍：一次一个，红框 + 前 / 后；左侧大数字 = 到前沿，**点“1 / 4”换下一个**，只列前方的。
  3. 果岭。
  - 三页都是：**表冠只管缩放**（1–4 倍），放大后拖动平移；未放大时上下滑翻页。
  - 测距：未放大时点地图放黄圈；**放大后长按 0.5 秒**放黄圈（避免拖动误放）；显示到黄圈码数和“再 N”到果岭；
    点黄圈取消。**还没开球时一律从发球台量起**（测距、三距离、方案路线），蓝点仍画真实位置。
  - 去掉“手动记杆 +”和每杆“刚才用哪支杆？”：测到挥杆震一下，底部闪“第 2 杆 · 一号木 231 码”，点它撤销。
- **本洞成绩**（走下果岭朝下一洞发球台走，或下一洞开球时自动弹出；不点确认则下一洞开球时自动保存）：
  - 总杆：左右滚动的数字带，中间最大，两侧相邻数字缩小变淡，拖动 / 表冠滑到中间变大；上下拖也可。
  - 推 / 罚：原地上下滚（不弹单独页面），一圈循环（推 0–5，罚 0–4，0 上面接最大值），停手即选定并收起。
  - 总杆自动不低于“推杆 + 罚杆 + 1”，不够时自动加（带动画）。
- **计分卡**：一屏 18 洞记分符号，点某洞改成绩，结束本场在此。
- **本场汇总**：球道 / GIR / 推杆 / 罚杆，保存并结束；“继续打球 / 放弃本场”需往下翻才看到。

## 4. 自动记杆：检测与推算

罚杆（下水、OB、不可打）**不猜**，由用户自己记。检测只负责把每一次动作分对类。

**动作分类特征**（前四项手表实时算，最后一项靠之后的 GPS）：

| 动作 | 击球前站定 | 转动 | 撞击 | 之后 | 处理 |
|---|---|---|---|---|---|
| 真击球 | ≥ 1 秒几乎不动 | 峰值 ≥ 3 rad/s，累计转角完整 | 尖锐，通常 > 3 g，< 12 ms | 离开原地 | 算一杆 |
| 试挥打地 | < 0.6 秒 | 与真挥杆相近 | 发闷，约 2–3 g，20–40 ms | 原地不走，很快再挥 | 同位置 60 秒内只留“最像击球”的一次 |
| 空挥 | 很短 | 完整或半截 | 无（< 1 g） | 原地 | 不算 |
| 打完原地比划 | 无 | 多半截 | 无 | 原地 | 不算，不顶掉刚才那一杆 |
| 推杆 / 试推 | 推杆 ≥ 1 秒 | 慢摆 0.3–2 rad/s | 推杆 0.25–1.2 g 小尖峰；试推无 | — | 只在果岭上判 |
| 坐车等 | — | 无挥杆式转动 | 可能很大 | 车速 > 2.5 m/s | 不算 |

“最像击球”打分：站定越久、撞击越尖越短、越大、之后越快离开，分越高；同分取最后一次。

**流程**：传感器（800 Hz 加速度、200 Hz 转速，需 Series 8+、锻炼模式）→ 挥杆分类 → 定位置（GPS
对照发球台 / 球道 / 长草 / 沙坑 / 果岭，精度 ≤ 12 m）→ 合并去重（手表 + 手机，相距 < 8 m 算同一位置）
→ 分洞（第 N 洞发球台开球进入；离开果岭 25 m 以上朝下一洞发球台走 = 结束）→ 推算成绩。

**推算**：总杆 = 算杆的挥杆 + 推杆 + 罚杆；推杆没测到时按第一推离洞距离估（< 1.5 m 1 推，1.5–15 m 2 推，
> 15 m 3 推，依据业余进洞率）；开球按第二杆位置；GIR = 第一推是第几杆 ≤ Par−1；球杆按距离对照球包猜，
不再每杆询问；什么都没有默认标准杆。

与现有代码：`WatchAutoShotDetector` 已有站定 / 转动 / 撞击 2 g 三项（撞击门槛对推杆太高）；
需新增：往回找挥动起点 + 累计转角（Apple WWDC23 做法）、推杆 / 切杆分类、撞击时长特征、车速过滤、
同位置聚类、候选无需逐杆确认直接进本场、手表球场包带球道 / 果岭 / 沙坑轮廓。

**门槛全部是起步值**：公开资料没有腕部三分类（全挥 / 推杆 / 试挥）准确率和数据集，撞击时长、车速、8 m 等
都是自定，需要用户戴表实打几场并在复盘逐杆核对作为首批标注。推杆能否稳定检测是最大未知数，所以“按距离估推杆”是常规路径。

## 5. 纠错回流（任何地方的改动都回到算法）

手表本洞成绩、手机计分卡、赛后复盘里的每一次改动都是一条纠错，对回当时的候选动作：

| 改动 | 学到什么 |
|---|---|
| 删一杆 | 该动作是假阳性（试挥、坐车等），相似动作门槛上调 |
| 加一杆 | 找当时被排除的候选改标为真（如撞击 1.7 g 未过门槛），下调门槛；附近无动作则记“没戴表”，不调 |
| 改推杆 | 调推杆门槛，并用真实推杆数修正距离估算表 |
| 改总杆 | 弱标签，按推杆和位置猜最可能错的那一次 |
| 改开球 / 挪位置 | 这块表在该球场的 GPS 偏差；同洞反复出错标记球道轮廓可能不准 |
| 换球杆 | 更新每支杆的实际距离分布 |
| 不改直接确认 | 正确样本，权重最低 |

所有候选（含被排除的）都保留特征值直到这一场复盘不再改动；个人门槛每场最多一小步、同类纠错 ≥ 5 条才动；
纠错只影响以后，不改已确认成绩。先调个人门槛，数据够了再换小模型并做个人微调。原始传感器数据不出手表。

## 6. 业界做法对照（来源见 `watch.html` 第“别人已经怎么做的”一节）

- Apple WWDC23：撞击尖峰 + 往回找起点 + 累计转角；数据约每秒一批，适合事后判断；需锻炼会话。
- Garmin AutoShot：只测全挥杆，推杆 / 切杆明确不测；戴前导手；球车旁试挥打地会误记。
- Golfshot：Series 8+ 自动数推杆（不量距离）；同位置多次挥杆以最后一次为准。
- 18Birdies：只带手机时把“停下来的位置”当候选击球点；旗位 + 第一推位置算第一推距离。
- Arccos：推杆撞击最轻、短推常漏，提供一键加 / 删推杆。
- 微软手环专利：开球 / 切杆 / 推杆分三个分类器。
- 主动学习研究：用用户纠正调模型，平均准确率约 +11%（因人而异）。
- 当时网络限制，多数网站只能看到搜索摘要，原话以链接为准。
