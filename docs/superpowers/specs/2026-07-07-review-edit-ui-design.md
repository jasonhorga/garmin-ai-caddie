> **整洞本地草稿**：点空白立即连续添加编号落点，长按编号拖动位置，点编号进入球杆/击球时球位

> geometry authority 为 `ready` 时才可作为最终 topo，partial 轮廓不得冒充完成态。现行代码与

> **目标**:review 每个球洞时,发现漏了一杆 / 记错了,能在满屏球道图上**亲手加、改、拖、删每一杆**,做到**干净、可靠、永不变砖**。对标 Garmin(抄它地图编辑的好、避它的坑),但更顺。
>
> **现状 & 范围**:后端修改层已上线(PR #250/#263/#265:稳定 shotId + op-based 修改 + 端点,支持删/改球杆·球位/每洞手填罚杆;**网页复盘 = 只读展示**已上线)。本设计是 **iOS 那套"满屏 + 能动手改"的交互**——负责人之前专门留着自己设计的那块。**网页保持只读,iOS 才是编辑器**(两端有别,负责人定的)。
>
> **对标依据**:Garmin 抱怨汇编([[garmin-gripes]] / funnel `/garmin.html`)——Garmin 能在两杆间插杆(地图上点一下),但**删空整洞即变砖、落点只能近似、重排有 bug、约 60–75% 报 "Unable to save"、无一键删、无撤销**。我们要赢的就是这些。**别碰它被爱的**:距离精度 + 简单直觉。

## 1. 两个模式,一张满屏图

- **看的模式(默认)**:满屏球道图(topo),所有杆画在上面(发球 → 各落点 → 果岭,每个落点标「什么杆 + 多远」)。手指**平移 / 缩放**;**切洞点底部洞条(绝不 swipe,免三种单指拖动打架)**;下面一条落点顺序列表(杆序 + 球杆 + 距离 + 球位)。
- **改的模式**:点「编辑」**显式进入**;进入后**锁住切洞**(免误触换洞)。显式退出。

## 2. 手势地图(理清,免打架)

**编辑模式里:**
- **空白处点一下 = 加一杆**(在你点的位置)。
- **按住某个落点的手柄 = 拖它**(改位置)。
- **点某个落点(或列表里那一行) = 弹框改它**(球杆 / 球位 / 删除)。

**看的模式:** 单指拖 = 平移;双指 = 缩放;切洞 = 底部洞条。

## 3. 加一杆 + 自动连线(核心)

**假设球都是往前打的。**
1. 编辑模式里,在图上**点一下** → 系统按"**前后两杆之间**"把这一杆**插到正确的顺序位**(用点的位置在球道推进方向上落在哪两杆之间来定序)。
2. **自动画两根线**:把新落点连到**前一个落点**、连到**后一个落点**(顺序对了,线就自然连上)。
3. 落点的**世界坐标由你点的像素位置反投影自动算**(overlay 投影的逆变换:像素 → lat/lon);**距离**由它与前一杆坐标推出。系统给个**推荐默认值**。

## 4. 弹窗确认 + 默认值

点这个新增的点 → **弹确认框**:
- **选球杆**:默认**高亮"按距离猜的那支"**(见 §7 缺杆逻辑),你确认或改;不点就留「未知」,**绝不替你写死**(守不造假)。
- **选球位**:球落在哪(球道/长草/沙坑/水/果岭/…),纯描述。
- **位置**:已由 §3 的点位自动算好、给默认值。
- 确认 → 存 → **回到落点列表状态**(见 §6)。

## 5. 拖动微调 + 放大镜

- 加完 / 选中一杆后,落点**可拖**。每个落点有一个**固定的拖动手柄**;**按住手柄或它附近的范围**就能拖。
- **放大镜(提案)**:按住手柄后,**手指上方**浮出一个圆形放大镜,显示手指底下(被手指挡住的)那块区域的放大图,拖动时实时跟随;**松手落定**。(抄 Garmin 的 magnified view,解决"手指挡住看不准"。)
- 拖动实时更新该杆的坐标 + 重算距离 + 重画它与前后两杆的连线。

## 6. 落点列表 + 顺序调整

- (a) 一个**落点顺序列表**,展示每一杆的前后顺序(球杆 + 距离 + 球位);**顺序可手动拖着调**(长按行拖动重排)。
- (b) 确认某个点后,页面**回到这个落点列表状态**;此时**点列表里任意一个点** → 再次**编辑或拖动**它(map 上高亮对应落点)。
- 列表与地图**双向联动**:点列表项 = 选中地图上的点;拖地图上的点 = 更新列表里的距离。

## 7. 缺球杆的默认填充

- 某杆 `club == null`(Garmin 记的 clubId 0 / 没记到)→ 选杆器**默认高亮"按这杆距离猜的那支"**(距离落在哪支杆的分布里)。
- **只高亮、不写死**:用户不确认就保持「未知球杆」;**推测绝不进球杆档案 / 统计**(守 [[garmin-gripes]] 说的、也守我们自己的不造假铁律,否则脏数据毒化 AI 选杆)。

## 8. 删除(极简)

- **直接删,不问原因、不做撤销**(负责人定:现在不需要)。
- **★ 永不变砖**:哪怕把一洞的杆**全删光**,照样能回到编辑模式**点地图加回来**(Garmin 这里会变砖、加不回;我们后端 op-based,加空洞天生支持)。

## 9. 其它

- **这洞罚几杆**:一个 **+/− 计数器**(手填一个数;同点重打只留最后一杆,罚杆自己填)。
- **球位 = 纯描述**,不跟罚杆/计分挂钩(负责人早简化过)。
- **保存永远成功**:本地先落(离线优先)、后台同步——不会像 Garmin 60% 报"存不了"。
- **没几何的洞**:满屏图退化成**纯列表编辑**(能删 / 改球杆·球位 / 罚杆 / 加无位置的杆)。

## 10. 要给后端补的(我之前只做了删 / 改球杆·球位 / 罚杆)

后端是 op-based,加这几个 op 很顺:
1. **`addShot` 的 apply**:按 {位置坐标, 球杆, 球位, 插在哪(前后杆之间的序)} 造一杆合成落点、排进顺序;shotmap 按序画线就自动连上前后。(op 已在 `VALID_OPS` 里,只差 apply + 端点校验。)
2. **改位置**:`editField` 扩到能改**坐标**(不只 club/lie);拖动落定时发一条。
3. **`reorderShot`**:落点列表手动重排 → 一条重排 op(需要设计"顺序覆盖":现在按 raw `order` 排,修改层要能覆盖顺序)。
4. **像素 → 世界坐标反投影**:点图/拖动给的是像素,要反投影成 lat/lon 存(overlay_projector 现在是 world→px,要加逆变换)。

## 11. MVP 边界

**进 MVP**:进出编辑模式(锁切洞)· 点地图加杆(自动插序 + 自动连线 + 弹框选杆/球位 + 位置由点位自动算)· 拖动改位置(含放大镜)· 点杆改球杆/球位 · 直接删(不问因、不撤销)· 落点列表 + 手动重排 · 罚杆计数器 · 缺杆默认高亮 · 永不变砖 · 无几何退列表。

**第二步 / 后置**:「这里可能漏了一杆」的缺杆自动提示(前杆落点↔后杆起点位移超阈值);更细的障碍属性(目前球位描述够用)。

## 12. 铁律 & 待核实(诚实留白)

- **不造假**:拿不准留空、推测不进统计、球杆推测只做选杆器默认高亮不写死。
- 待做计划时核实:① 像素↔世界坐标逆变换的精度(和现有 world→px 一致);② "顺序覆盖"怎么和 raw `order` + 稳定 shotId 共存(reorder 后 shotId 不变);③ 满屏 + 拖动 + 缩放三种手指操作的边界(拖手柄 vs 平移 vs 缩放不误触);④ iOS 编辑器要真机/TestFlight 才能真正验手感(CI 只验编译 + 快照)。
