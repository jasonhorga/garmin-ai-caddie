# AI Caddie 设计系统与设计原则(手表 / iOS / Web)

2026-07-03 · 由三路 Fable 设计评审收敛(HIG 规范 · 配色实测 · UI/组件一致性)。配套统一 spec `2026-07-02-unified-tri-surface-spec.md`,设计相册见 funnel `/gallery.html`。

## 现状判断

**三端现在不是一套设计系统,是三个各自成立的方案。** 手表最成熟(暗底/大字/F.C.B 层级,和 Garmin S70 范式同构);iOS 是标准浅色 app,但打球屏丢了 Garmin 的核心(大字距离);Web 是工程师仪表盘(灰阶塌陷、无网格、后端配置泄漏)。三端"同一个东西"—— 洞图、球童卡、距离数字、成绩色 —— 没有一个长得一样。**把三端各截一张拼一起,陌生人应当三秒内认出是同一个产品;今天做不到。**

---

## 五条北极星

1. **手表是原点。** 打球面的设计语言从手表版**反推**到 iOS 实战屏,不是从 iOS 摊薄到手表。手表已打样成功。
2. **两种面,一套 token:打球=暗色玻璃,复盘=亮色纸面。** 打球面(手表全部 + iOS 实战/记分屏)强制暗色(OLED 阳光下高对比 + 对齐 Garmin 习惯);复盘/备战面(iOS 其余 + Web 全部)亮色纸面。所有颜色 token 双值(dark/light),同一 hue。
3. **数字是主角。** 每个打球屏有且只有一个主读数,主读数字号 ≥ 2× 次读数(Garmin 中间数原则);数字一律等宽(tabular figures)、中性色,**禁止用颜色区分前/中/后**。
4. **同物同形。** 洞图、球童卡、距离栈、成绩徽章、球杆 chip、步进器 —— 六个核心组件三端共用同一份字段表、同一配色、同一字形字典,只允许尺寸与交互方式随端变化。
5. **Garmin 语法,Apple 语感。** 打球范式(F/C/B 栈、成绩色标、实打 ±、大字模式、旗向红箭头)向 Garmin 对齐(降低 S70 用户迁移成本);控件、动效、可达性(动态字体、触达尺寸)按 Apple HIG。

## 一、色彩(全端实测校准过,带对比度)

### 品牌 / 动作绿(唯一的绿,白名单三处:主 CTA · 推荐 chip · 进行中状态点)

| Token | Light(iOS/web) | Dark(手表) |
|---|---|---|
| brand.primary | `#15803D` | `#30D158`(Apple systemGreen dark,同 hue 家族) |
| brand.tint(选中底) | `#DCFCE7` | `rgba(48,209,88,.16)` |
| brand.border | `#86EFAC` | — |

> iOS 现在的病是"品牌绿通货膨胀"—— 绿同时做 header 底/按钮/链接/选中/图表/选中球杆,灵魂时刻(球童推荐)反而不 pop,而且 caddie 表"推荐"chip 竟然用**蓝**。绿必须收进白名单;链接改 `#374151`+下划线、选中态改浅绿 tint、图表走中性+语义色。

### to-par 成绩色(全端一套;**Par 用绿**,赤橙黄绿青蓝紫色阶 + 圈/方形状冗余)

> 2026-07-03 负责人拍板 + 三模型对抗确认,**推翻上一版"Par=中性避绿"**。色相走自然彩虹序、Par=绿(视觉舒服);防色盲不靠色相,靠**数字 + 圈/方形状**双重冗余(见下)。

| 成绩 | 形状(不依赖颜色) | Dark(打球黑底) | Light 文字(复盘) | Light chip 底 |
|---|---|---|---|---|
| Eagle −2 | ◎ 双同心圆 | `#60A5FA` | `#1D4ED8` | `#DBEAFE` |
| Birdie −1 | ○ 单圆 | `#7DD3FC` | `#0369A1` | `#E0F2FE` |
| **Par 0** | **无框**(靠"没框"识别) | `#4ADE80` | `#15803D` | 无底 |
| Bogey +1 | □ 单方 | `#FDE047` | `#A16207` | `#FEF9C3` |
| Double +2 | ⊡ 双同心方 | `#FB923C` | `#C2410C` | `#FFEDD5` |
| Triple +3 | △ 警示三角 | `#F87171` | `#B91C1C` | `#FEE2E2` |
| ≥+4 更差 | △ 警示三角(紫) | `#A78BFA` | `#6D28D9` | `#EDE9FE` |

> **Par 绿之后红绿色盲怎么读**(三重冗余,任一通道都够):① 数字与 ±杆号永远在(E / −1 / +2 直读),色只是快速扫视层;② 高尔夫转播传统的**圈/方/三角**外框——低于标准杆=圆(Birdie ○ / Eagle ◎)、高于=方(Bogey □ / Double ⊡)、Triple+ = △ 警示、**Par=无框**;色盲用户看形状即读,转灰度也一眼分;③ 明度随 to-par 幅度单调,灰度仍成梯度。上线前跑一次 WCAG AA(浅黄/浅蓝 chip 配深字)。手表 bezel 极小尺度也靠圈/方一眼辨。**移除 iOS 现在的粉红超杆 chip**;现在"+1"手表黄 / iOS 粉 / web 琥珀三套矛盾,统一为上表。

### 功能语义(固定绑定,禁止挪用)

- **推荐** = brand.primary 实心 chip 白字(三端同);
- **警示/风险** = 琥珀 `#FFD447`(dark)/ 文 `#B45309` 底 `#FEF3C7`(light);
- **危险打法/错误** = `#FF453A` / `#DC2626`;
- **蓝**只保留两个岗位:**under-par 成绩** + **水域填充**(现在蓝同时干六份工:前沿距离/小鸟/球道率/蓝T/测距线/水);
- **Tee 色**(蓝白金红)= 物理色,仅以带描边小圆点出现在 tee 上下文,永不挪用;
- **灰阶** light:`#111827`/`#374151`/`#6B7280`(`#9CA3AF` 仅 placeholder);dark:`#FFFFFF`/`rgba(235,235,245,.6)`/`#8E8E93`。

## 四、六个核心组件跨端规范(每件一份,收益从大到小)

1. **HoleMap(最优先)**:单一几何管线 → 三端同 course palette + 同覆盖字形字典(球=白点1px深描边 / 旗=红旗 / 目标=白十字环 / 距离签=黑底白字圆pill带方向箭头 / 落点=按杆型色点+深描边)。iOS/Web 只是更大可交互,不许另起画法;**Web 备战逐洞的白底散点示意图废弃**,换同一渲染。(2026-07-03 定:**底图用我们自绘的 topo 战术风**——服务器预渲位图 + 客户端叠矢量层;Garmin 官方 raster 因签名/授权只作内部质检、不入产品,详见 §八 + 统一 spec §渲染架构。叠加层字形字典三端相同。)
2. **DistanceStack(前/中/后)**:后上·中大·前下,中间 2× 字号,标签灰、数字全白。用在:手表大字屏 · **iOS 实战屏头部(替换现在那个显"—"的小 stat 盒)** · Web 备战洞头。
3. **CaddieCard**:固定槽位与顺序 = 推荐杆 → 目标点 → 码数 → 打法档(护分/标准/进攻)→ 一句理由。手表=两行压缩、iOS=完整卡、Web=沙盘侧栏,**字段与词汇逐字一致**。概率类统一降级为风险档(低/中/高 + 色点),UI 不出裸百分比(D2/D3);低置信数据统一样式:灰字 + 「参考」徽章。
4. **ScoreChip**:相对标准杆徽章,统一色标(§一 彩虹色阶,**Par 绿**)+ **圈/方/三角形状冗余**(色盲可读)+ 填充 chip;手表洞圈/记分卡、iOS 历史、Web 复盘全替换(Web 那两根绿蓝大色条废弃)。
5. **ClubChip**:命名唯一化 **「1号木/3号木/7号铁/PW」**(阿拉伯数字 + 杆型);选中=green 实心白字,未选=描边。收敛掉 iOS 中文数字杆名、手表「3木」缩写。
6. **Stepper(记分 +/-)**:以现 iOS/watch 形态固化尺寸与热区(≥44pt),Web 补记一局复用。

## 五、两条硬约束(可写进 CI)

1. **对比度**:地图上任何图形 ≥ 3:1、任何文字 ≥ 4.5:1(户外场景自查;现有 DesignSnapshotTests 产物可直接跑对比度脚本)。
2. **一个色相在同端最多两个语义,且不得跨越"信息/警示"边界。**

## 六、各端要修的(HIG + 视觉,按优先级)

**手表(系统级 + 无障碍,最急):**
- 打球屏**保留系统时间**(一场 4 小时,手表首先是表)· 设计 **AOD 常亮态**变体(黑底只留洞号·Par + 到果岭中距离)· 出一枚**表盘复杂功能**(进行中显示"第N洞·到果岭287")· **「放弃」改红色 + 二次确认** · **横滑换打法改竖向分页 + 表冠**(避开系统返回手势)· 成绩**不只用颜色**(加 ±杆数/图例,色弱可读)· 底缘教学文案改浮层几秒消失 · 记分/选点支持**表冠精调**。

**iOS:**
- **实战屏换 DistanceStack 头部**(距离是第一公民)· 支持**深色模式**(打球屏强制暗)· **动态字体**(stat 胶囊 AX 档改纵向堆叠避免溢出)· 选择控件用**列表勾号**不用圆圈 radio · "Unknown course"→「未命名球场」· 「保存本洞」固定为底部悬浮 · **洞图升级到手表同源渲染** · 顶层若坚持首页三件事,保证每二级页边缘右滑返回 + 进行中卡全局可达。

**Web:**
- **设置→后端配置整页门控进 owner 诊断**(最反 Clarity)· 备战/沙盘白底散点**换真实洞几何底图** · 控件 36–44px、正文 ≥14px · 加 **max-width 1120 网格**、补齐主页死白 · 图表给足高度(折线 ≥240px)、单样本不画满宽条 · fail-AA 的琥珀条/蓝块改深字或换色。

**跨端一句话**:先定 **to-par 色板** 和 **course palette** 这两张表(三端照抄),"像同一个产品"和一半无障碍问题就解决 70%。

## 八、洞图渲染风格 + 数据/渲染架构(2026-07-03 三模型对抗结论)

**关键前提纠正:自绘渲染不慢。** 生产 `hole_render.render_hole` 实测 **0.45s**;此前"v1 7.5s"里 6.7s 是一段可删的幼稚水深滤波(超采样画布上跑 6×MinFilter),换 numpy 距离变换后仅几十毫秒;富渲染(地形光影+树+水+沙)优化后 ~1s。**"渲染慢→必须端上渲/上矢量瓦片"的前提不成立。**

**渲染风格(Q2,三家一致:走 topo 战术风、不抄 Garmin 插画、保留 3D 阴影):**
- **方向 A(主推)地形等高线 / Editorial Topo**:真高程做 hillshade + 环境光遮蔽当主角;球道/果岭**去饱和哑光平涂**;叠**从同一高度栅格抽的细等高线**(每 1–2m 一条);树=小而统一的深色点 + 短投影(不画插画树冠);水=墨蓝 + 单条岸高光。观感=高级码数手册/地形图,是**数据诚实的识别度**,和 Garmin 玩具 3D 完全不同;等高线成本≈0(高度栅格已为 hillshade 而建)。
- **方向 B 暗色战术图**:炭灰 rough / 球道略亮 / 障碍微光 / hillshade 低调高光,直接贴"打球=暗色"北极星,不会和 Garmin 明亮日间风混淆。
- **不走**:Terrain.webp 逐像素贴图 / 照片级——需补 Draco 的 UV(现解码器只解 POSITION),投入大且更像抄 Garmin。放大后的锐利细节交给**矢量叠加层**(距离环/标签/落点/球),矢量无损缩放永远清晰,不需要 gigapixel 底图。

**数据 / 渲染架构(Q1,2 家主张 vs 1 家异议,完整版见统一 spec §渲染架构):**
- **主张(Fable + GPT-5.5)**:服务器 = 唯一真源 + 唯一位图渲染器;**服务器预渲成品位图底图(light 复盘 / dark 打球两套)+ 客户端只叠一层薄矢量交互层**(路线折线 / 障碍距离区间 / F·C·B / tee / 可拖的球 / 实打 ±)。**手表永不渲 3D、永不解网格**,只拿成品位图 + 极少 native overlay。存储非约束(几万球场全量 ~100–175GB,存我们自己的 CoursePack、不存解码 JSON)。选场时预取 **5–15MB/场离线包** → 开局瞬时、全程离线;热门全量预渲、长尾按需补齐但不阻塞开局。
- **异议(Gemini)**:客户端跑 3D(iOS Metal 实时渲几何),换无损缩放 + 动态光照。**被 GPT-5.5 驳**:手表耗电/发热/延迟不可接受、手机不该把开局体验押在解网格+3D 上。→ **采纳折中:手表 / 手机打球走「位图底 + 矢量叠加」;Web 备战大屏才用 WebGL 3D**(有算力、无手表约束,拖着看整洞值)。
- **⚠️ 授权红线(GPT-5.5 提,别人都漏)**:Garmin 官方 raster "匿名可下 + 签名会过期" **≠ 商用授权**;签名 URL 不能当产品资产、不能暴露给客户端。**产品底图用我们自绘(topo 风,已证能渲得一样好),官方 raster 只留内部质检对齐**——除非拿到授权。这**推翻**了 `2026-07-03-garmin-data-to-features.md` 里"洞图以官方精绘 raster 为底"的旧结论(该文第 1 档 #1 与 §一致性两处需按此更新)。

## 九、洞图渲染标准(2026-07-04 锁定:精致写实 topo · 自绘)

经 v1→定稿多轮打磨(负责人逐条视觉评审 + Gemini/Codex/Fable 评审 + 三风格选型:吉卜力水彩 / 扁平矢量 / 写实)→ **定为「精致写实 topo」自绘风**(不用 Garmin raster,授权红线见 §八 / 统一 spec 附录 C)。原型脚本 `assets/hole-render-topo-prototype.py`(gid31795 h1;standalone,不碰生产 `hole_render.py`),定稿图 funnel `/render-final.png`。三端底图照此(服务器预渲位图)。

**锁定的规则:**
- **取景**:tee→果岭竖直;按洞包围盒 fit 高度、宽度补到 **~0.64 竖幅比例**、洞居中、两侧留天蓝(不贴死裁成竹签)。
- **朝向**:自然投影,水在**右上**(与 Garmin 同向)。
- **光**:太阳在**右下(SE)**,所有树影/暗面在**左上(NW)**(与 Garmin 一致)。
- **地形**:hillshade 极淡(≈±7% 明度)、**无 AO**(AO 会把高程异常网格面压成三角 bug);高程栅格重度平滑(10×SS)。
- **球道**:硬边斜向割草**亮带**(只提亮 +6%、绝不压暗)+ 一层很细的**草皮颗粒**(±3.5% 高频)。禁:低频 mottle(显脏)、柔和正弦条纹(发晕)。
- **二级草**:双色 fbm 斑驳(有机纹理)。
- **树**:55 棵按物种 id(1–9)分明暗/大小;broccoli 碎边 + **平滑方向渐变**(SE 亮 NW 暗)+ 细颗粒 + 单独一层柔和落地投影(offset NW)。树只落两侧 rough、不落球道。禁:偏移半透明圆做高光(出暗点/月牙鬼脸)、「树林区」整块压暗(出角状几何块)。
- **果岭**:白色目标环 + 旗钉在**真实本洞果岭质心**(按打球线终点聚类,避开邻洞果岭)。
- **沙**:颗粒 + 耙边阴影。**水**:只画和果岭连通的本洞水体(断开的邻洞水/邻洞轮廓都裁掉)+ 浅深渐变 + 波纹 + 亮岸。
- **边缘**:超采样 + 细描边(球道/果岭/沙);**不靠高斯模糊柔化**(会发糊)。
- **Tee 台**:平整小块,**不加条纹**(细纹会变"条纹硬币")。
- **不进底图**:打球线 / 码数 / tee 点(都是打球时按球杆/GPS 的**动态矢量叠加层**,不属于地图)。
- 渲染实测 ~7s@SS2(**批量预渲、不在请求路径**);生产可换编译级栅格器压到 <300ms。
