# Web 产品重设计 — 信息架构与核心界面

- 日期:2026-06-09(2026-06-10 改为中文版,内容同步最新决策)
- 状态:设计已与用户逐屏确认(visual-companion 头脑风暴;mockup 在 `.superpowers/brainstorm/*/content/`,未入库)
- 范围:`web_v2`(主)、`server_v2`(少量新增 API)、`ai_caddie`(新增击球分析模块)
- 本次不做:iOS/watch 原生重设计、NAS 托管、`integration/v2 → main` 合并

## 1. 问题

`web_v2` 功能很全,但呈现是"工程仪表盘",不是产品:

- 12 个平铺顶部标签(Overview…Settings),产品功能和内部管道混在同一排。
- 诊断类(readiness、数据质量、对账、后端配置)和核心功能平级出现。
- 除比分配色外没有设计系统;`App.tsx` ~47KB、`CaddiePage.tsx` ~66KB 的巨石文件。
- 产品三大核心职能没有清晰入口:"备战"被埋没,"实战"像开发者调试页。

iOS 同样的病(平铺 List + fixture 数据)。按 2026-06-07 的决定:本次 **web 优先**,对着本机真实数据(461 场 / 105 球场)重做;设备端后续沿用同一套设计语言。

## 2. 产品定义 — 用户的三大核心职能

1. **历史(复盘)** — 对全部已记录球局的汇总统计与回看。
2. **备战(预热)** — 为即将要打的某一场(新、旧球场都行)出一份攻略,通常提前几天阅读。
3. **实战(记录+引导)** — 打球过程中:记录每一杆;根据**当下具体情况**给下一杆建议。主战场是手表/手机(设备阶段,暂缓);web 先做沙盘 + 回放。

## 3. 已确认的设计决策

(2026-06-09/10 可视化头脑风暴中逐条与用户确认)

| # | 决策 |
|---|---|
| D1 | 外壳 = 图标+文字左侧边栏:概览 / 历史 / 备战 / 实战,底部固定「设置」(mock `nav-style.html` 方案 A)。 |
| D2 | 历史 KPI 行 = 均杆(18洞) · 差点(估算) · 得分区间 · 帕或更好率 —— 只这四个;"单场最佳"删除。 |
| D3 | 范围切换 全部 / 近12个月 / 近10场,驱动整个「历史·趋势总览」页;窄范围显示 vs 全部的差值。不再加其它档位。 |
| D4 | 备战是一级功能;用户会提前几天阅读。 |
| D5 | 不存在面向用户的「装载到设备」概念。离线打包只作为设备阶段的隐形后台管道。 |
| D6 | 任何地方都不绑定"下一场"。备战入口 = 任意球场搜索 + 常打球场直达(用户选 B)。用户几乎天天打,要备的常常不是下一场。 |

| D9 | 个性化提示必须由真实击球数据算出(如"近10场开球右偏 62%"),不许套话。 |

## 5. 页面规格

### 5.1 概览(落地页)— mock `home-page.html`、`home-page-v2.html`
- **备战入口卡(主位,按 D6):**"想备哪场?" —— 球场搜索框(支持中文,`/api/v2/courses/search`)+ 2–3 个常打球场(来自已打库:场次、均杆),直达其备战页。
- **上一场卡:** 总杆、±Par 徽章、球场、日期、一句亮点+失点;链到该场详情。
- **近期状态卡:** 差点+趋势差值、均杆、近10场迷你曲线;链到历史。
- **本周该练横幅:** 强弱分析里的头号漏杆点,带链接。

### 5.2 历史 — mock `history-overview-v2.html`
二级导航:趋势总览 / 球局 / 强弱分析 / 球场 / 报告。
- **趋势总览:** 范围切换(D3)+ KPI 行(D2,带 vs 全部差值)+ 成绩走势(折线;近10场逐场打点,其它范围按月聚合;杆数/差点切换)+ 成绩构成(老鹰→双柏忌+ 的条形分布 + 头号漏杆点一句话)+ 最近球局列表。
- **球局:** 现有时间线+筛选(年份/球场/有击球/有报告)换新皮;球局详情 = 逐洞计分条、逐洞击球图、问题标签、媒体。
- **强弱分析:** 合并 Holes/Clubs/Issues,再加击球派生指标:三/四/五杆洞表现、最难洞、各杆距离(含 Garmin `adviceDistance`)、开球方向偏置、GIR(标准杆上果岭)、球道命中率(依赖几何)、开球距离、攻果岭离旗分段、推杆(估算)+三推率(估算)、救帕率、小鸟/场、爆洞率(双柏忌+)。估算指标在 UI 里明确标注「估算」。
- **球场:** 已打球场列表(场次、均相对Par、最好)→ 球场详情(逐洞平均超帕条、趋势)→「去备战」链接。
- **报告:** 现有年度/季度/AI 报告,套新外壳。

### 5.3 备战 — mock `prep-page.html`(已按定稿去掉「装载」按钮与日期绑定)
- **入口:** 搜索任意球场(匿名 CourseView 搜索,中文 ≥2 字)+ 常打/已打球场直达。
- **球场头部:** 名称、par/码数/T 台(CourseView)、你的战绩(N 场、均杆)。不绑日期。
- 二级 概览 / 逐洞攻略 / 针对你:
  - **概览:** 关键洞(已打球场 = 你历史最差的洞;新球场 = HCP 最难 + 危险特征标记)+ 逐洞速览条(颜色 = 你在该洞的平均超帕;新球场中性色)。
  - **逐洞攻略:** 逐洞真实几何渲染(后端已有 `hole_render` / course-prep)+ par/HCP/长度 + 你的历史落点散布叠加(已打球场)。
  - **针对你:** 按优先级排序、带数据出处的提示 = 个人倾向 × 球场特征(例:右偏 62% × 5 个长四杆右侧有水 → 瞄左半球道)。确定性计算(D9)。

### 5.4 实战 — mock `live-play.html`
- **北极星(设备阶段,现在定设计):** 手机 = 当下情况卡(📍球位状态自动、🚩距离、🌬️风、⚑旗位)→ 建议卡(球杆、瞄点、绑定当下条件的理由、风险、稳/博)→「记录这一杆」。手表 = 距离+风 / 球杆 / 瞄点 / 风险徽章,一瞥即走。
- **计分(类 Garmin,已确认):** 洞分由所记录的杆自动累计 —— 没有单独的"记分"操作;收洞时确认推杆数即可。页头常驻相对 Par 总分("本场 +6");点开有完整 OUT/IN 记分卡。收局自动存为「历史」里的一场正式球局。默认比杆;定点积分(Stableford)/净杆(按差点)做后续制式选项。若 Garmin 表同时记了同一场,后端现有 mobile reconciliation 自动合并,不重复计数。
- **本次 web 范围:** 重做 Caddie 页 = ① 最近一场回看 ② 决策沙盘 —— 选球场/洞,在洞图上摆球位、设风/球位状态 → `/api/v2/caddie/decision` 出建议 + 稳/博切换。web 不假装有 GPS。

### 5.5 设置
现有 Settings / Sync & Data Quality / Corrections / Garmin 会话移入,只换壳、不深改。

## 6. 设计语言

- **Token(CSS 变量):** 主绿 `#15803d` / `#22c55e`、浅绿底 `#e7f3ec`;页面底 `#f6f7f8`;卡片白、圆角 14–16px;描边 `#e7e9ec`;墨色 `#0f1720`;次要 `#6b7280`;比分语义沿用现有 token(帕绿系、柏忌琥珀 `#d39a45`、双+红 `#b55349`;mockup 用的 `#d9a441`/`#c2553f` 是否在 W1b 替换待用户决定)。
- **字体:** 系统字体栈;比分一律等宽数字;正文 ~13px,KPI 数字 26px;界面中文优先。
- **核心组件:** 侧边栏项、二级页签、KPI 卡、面板(+头)、分段控件(范围、稳/博)、比分徽章、逐洞速览块、提示行(严重度圆点)、建议卡、搜索框、球场行。
- **图表:** 沿用轻量内联 SVG(同现状),不引图表库。

## 7. 数据底账(2026-06-09 已核实)

- 本机真实数据:461 记分卡 + 461 击球文件 + 105 球场文件 + `summary.json`(461 条摘要);`data/` 软链,gitignored —— 只在本机。
- 每杆:`startLoc`/`endLoc`(WGS84)、`meters`、`clubId`、`shotType`(TEE/APPROACH/CHIP/LAYUP/RECOVERY/UNKNOWN)、`excludeFromStats`;每洞:`pinPosition`、`holeImageUrl`;球杆档案:`averageDistance`、`adviceDistance`。
- **可直接算:** 开球偏置、GIR、开球距离、离旗距离、救帕、各杆距离。**依赖几何:** 球道命中率、渲染叠加(CourseView 多边形;覆盖度因球场而异 → 优雅降级:藏掉该指标、回退 `holeImageUrl` 或 par+长度卡)。**仅可估算:** 推杆与三推(洞杆数 − 已记录杆数),标注「估算」。**没有:** 罚杆。
- 天气缓存仅 1 个文件 → 实时条件由设备阶段现取;不做回填。
- 性能红线:历史统计有指纹缓存(热 ~0.2s)。范围切换与新增击球分析必须热 <1s —— 同样的缓存待遇。
