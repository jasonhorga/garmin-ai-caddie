## 1. 这是什么产品 · 三个端各干什么

AI Caddie —— 一个高尔夫 AI 球童。对标 Garmin S70 那种手表体验,靠「AI 球童给建议」做出差异。**四条铁律:不显示成功率/百分比、距离一律用码、界面简体中文、断网也能用、绝不编造数据。** 产品名就叫 **AI Caddie**,不显示个人名字。

| 端 | 干什么 | 长什么样 |
|---|---|---|
| **Apple Watch** | 打球的主力(一切以它为原点) | 深色、大数字、地图 |
| **iOS 手机** | 打球时的场上控制台,也能只用手机打完整场 | **打球界面深色**(跟手表一个样);**其它页面(首页/复盘/备战/统计/球包/设置)浅色、原生 iOS 风** |
| **网页** | 复盘 / 备战 / 统计 / 球包(不用来实时打球) | 桌面工作台、亮色底、深色导航栏 |

**几条北极星:** 手表是原点 · 打球深色、复盘亮色 · 数字是主角 · 同一样东西在三端长一个样 · Garmin 的用法 + Apple 的手感。

## 2. 设计系统(细节见附录「设计系统」)

- **颜色**:品牌绿只在三个固定地方用;**成绩颜色按「差几杆」走彩虹 —— Par 是绿色**,好于标准往蓝紫走、差于标准往橙红走,再配上圆圈/方块/三角的形状(色盲也能分)。一套球场配色三端共用。
- **球洞图长什么样(已锁定)= 手绘的精致写实俯视图**:洞要**填满整个画面**、光照固定(太阳在东南、影子朝西北,跟 Garmin 一致)、干净的割草条纹、有树、果岭上有目标圈 + 旗子、只画跟本洞相连的水、边缘描细一点。**图上不烤进打球线、码数、发球台标记** —— 那些是盖在图上面的一层「贴纸」(矢量层),可单独换。样板 `assets/hole-render-topo-prototype.py`,正式版 `ai_caddie/geometry/topo_render.py`。

## 3. 怎么搭的(细节见附录「统一 Spec」附录 C)

- **后端是唯一的数据源 + 唯一画图的地方**:后端把球洞图画成成品图片(画一次存起来),客户端只在上面盖薄薄一层贴纸(路线 / 落点 / 距离 / 球位)。**手表永远不做 3D 渲染**(太耗电),网页大屏才可能上更炫的画法。
- **数据和准备只在后端做一次、三端都来拿**:球洞图渲染 + 缓存 + 提前备料、球杆识别、落点图数据 —— 都后端出,手机/网页/手表直接用;**一开始打球,后端就把这局要用的都备好。**
- 一条法律红线:Garmin 官方那种带签名的地图不能商用,所以底图我们自己画。
- 存储不是问题(几万个球场约 100–175GB);选球场/开局时把离线包提前拉下来。

## 4. 现在到哪了(2026-07-05)

- **网页全套重做 + 真实球洞图**:已上线真站 `/me`。
- **iOS 全部主页面换新皮**:打球深色、其余浅色,已进主线(上架 TestFlight 等负责人点头)。
- **球洞图渲染流水线**:后端有个地址 `GET …/courses/{球场}/holes/{洞}/topo.png`(画一次存起来),还有个「提前备料」接口,三端的球洞图都从这里拿真图。
- **刚修好并上线的两个共享层问题**:① 球洞图以前只占画面一小块、漂在中间 → 现在**填满整个画面**;② 复盘里很多杆显示不出来(显示成 Unknown)→ 现在**认得出你用的哪支杆**,认不出的就干脆留空、不再显示 Unknown。

## 7. 复盘 v2 设计(已出设计 + 三模型对抗评审收敛,2026-07-05)

> 负责人:§7 是让我**出设计 + 对抗 review**。已产出完整设计草案 → 3 模型(Codex gpt-5.5-xhigh / Gemini 3.1-pro / Fable)独立对抗评审 → 收敛。三家一致:草案「方向对(双层模型+provenance 是正解),但**不能直接实现,先修三处硬伤**」。**完整设计见附录 `2026-07-05-review-v2-design.md`(funnel `/rv2.html`)**,下面是提要。

**目标**:复盘每杆做到「**什么杆 + 多远 + 落在/打进哪 + 罚没罚**」四要素完整、可信、可修。用户能增/改/删杆修 Garmin 的漏记/错记。**不造假**(留空胜于瞎猜、不重复计罚杆、推测绝不进统计)。

**三家一致的三处硬伤(已在设计里修掉):**
1. **数据身份**:`roundId:hole:order` 当稳定 ID,会在 Garmin 重同步/多源(Garmin+手表+未来 AutoShot)下错位。→ ingest 铸造**稳定 ID** + 修正层改 **op-based 事件日志**(顺带白送撤销/离线/审计/AutoShot 共存)。
2. **罚杆不该绑在落点**(评审对)—— 但**负责人拍板极简**(2026-07-05,覆盖评审的过度设计):罚杆 = **每洞手填一个数** `manual_penalty`,系统不管 OB/救济/怎么抛(别做 relief_event/坐标断裂那套);**同点重打只记最后一杆**;球位只描述「球在哪」不跟罚杆挂钩;洞分 = 去重杆数 + 手填罚杆。
3. **整洞 PUT 覆盖 与离线优先自相矛盾**(多端静默吃修正)。→ 已并入 op-based。

**其余收敛结论:**
- **缺杆:检测 > 推测**。漏记的正解是「前杆落点↔后杆起点位移超阈值 → 提示可能漏了一杆」;缺球杆名降级为「未知+手动选杆」,推测只当选杆器默认高亮、不写「7号铁?」;**inferred 永不进统计/球杆档案**(否则毒化 AI 选杆),Garmin 距离是直线位移非击球距离。
- **交互手势定死**:满屏图查看态只平移缩放,切洞用底部洞条(不 swipe),拖落点长按拾起;新增杆=从列表「第N杆后插入」起点=前杆落点(一杆拆两杆+重算);删杆带删因+撤销。
- **网页不该只读**:改球杆/球位/罚杆的纯表单编辑第二步就开放网页(大屏批量修是重度用户刚需);只读端也必须展示 provenance。
- **MVP 重排**:进 MVP=稳定ID+op-based / **每洞手填罚杆数** / 删杆+撤销(同点重打只留最后一杆) / 洞分=去重杆数+手填罚杆 / 缺杆检测 / iOS 满屏+手势定死;**降级** club 推测;**v2.1** 拖动改位置、网页几何编辑、导出。
- **更深的方向(负责人提)**:我们**没有自己的挥杆检测**,复盘的杆全来自 Garmin 设备(会漏记/错记)——手动修正是在兜它。研究初稿说「可行」,但**经 Codex + Gemini 对抗评审大幅下调:这只是「受控验证假设」,不是可行性结论;第一步不该是 AutoShot**。技术能做,但「冲击=主判据」物理站不住(擦地试挥比干净扫球冲击还猛)、「震动确认」会毁体验、续航/后台/冷启动数据都是硬门槛。**近期主线应转「一键记杆按钮 + 自动GPS + 默认球杆」+ 静默影子采集 + 真机5h续航实测,AutoShot 无限后置到真实18洞数据把误报/漏报/续航都证明过线。** **完整报告 + 评审记录见附录 `2026-07-05-auto-swing-detection.md`(funnel `/swing.html`)**。门控:等负责人拍板优先级。
