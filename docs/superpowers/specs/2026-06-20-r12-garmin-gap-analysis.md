# R12 设计与开发准备(对比 Garmin / GolfLive)

> 2026-06-20。用户看完 TestFlight 0.1.0(31) 后的反馈 + 21 张参考截图(`~/claude-web-data/IMG_4878–4896` + `4917/4918`)。本文是**当前完整设计**,供用户与 Codex 审阅。未开始实现。

## 0. 定位与架构(本轮的核心转向)

- **产品定位**:对资深用户 = 仍用 Garmin 打球,**我们做备份**;对**没有 Garmin 设备**的用户 = 用 **Apple Watch 独立**打整场。
- **三端互通**:手机 / Web / Apple Watch,任一端开局,另两端**实时可见 + 可同时操作**。**后端事件日志 = 单一真相源**(已有 `/api/v2/mobile/rounds/{id}/events` 批量 ingest + replay)。
- **Apple Watch 独立完整球局**:开局 → 逐洞记分 → 结束,离手机也能打(手机仅作网络通信/同步)。当前 Watch 仅是**配套件**(`mobile/ios/AICaddieWatch`:`WatchRoundState` 镜像 + `WatchInputView` 部分输入 + `WatchSyncClient` 341 行联网,共 913 行)→ 本轮要**角色反转**成独立 app。
- **自动记杆(AutoShot 式)**:Apple Watch 运动传感器(加速度计+陀螺仪)检测真挥 → GPS 记击球点 → 连续两杆 GPS 差 = 该杆真实距离;球杆 = 用户确认 or 默认 AI 推荐杆。手机不必做挥杆检测。
- **球杆距离**:**直接同步 Garmin 每杆平均距离**(它有详细记录;最大距离不重要);本地自测(杆+GPS)留作以后整合。注:`/club/player.averageDistance` 历史上为 0(见 garmin-club-endpoints),平均距离在另一个「挥杆统计」端点上,需探。

## 1. 竞品对照(修正归属后)

- **Garmin**(用户确认):打球流程 = 选球场(按距离+下载) / 选 Tee(带 rating·slope) / 回合设置(**起始洞任意** + 球场差点 + 计入统计开关) / **写实 2D 球洞大图**(平移·缩放·移动目标测距,阴影圈当前洞,既美又实用) / 极简录分(杆·推·罚 + **球道 ↖命中✓↗ 三向**) / 跳洞 / 恢复回合 / **挥杆统计**(每杆正常发挥距离,9铁=137 是对的) / 我的球包。
- **GolfLive**(用户确认,我先前误标成 Garmin):**统计/历史** = 历史列表(每场 + **逐洞红黄绿色条** + 环标) / 球场统计(全部·前9洞,**分布点阵图** 平均杆·GIR·每洞推杆 + **开球左中右雷达**) / 球场记分卡(**按年**) / 单场记分卡(**标准杆·帕·高于标准杆** 计数 + 球道·GIR);用户要的维度还含 **小鸟/帕、按季度/年/球场**。
- **我们现状**:手动记分(`CurrentHoleView` 手机为主)+ AI 球童(序列/选杆/避开区)+ 复盘 + StatsView(round-9/10 已有按季度/各球场/抓鸟保帕/趋势,但**工程味重**)。差异点 = 球童。

## 3. 三项正确性根因(已定位,纯后端为主)

- **1.1 复盘截断 9 洞**:`ai_caddie/history_round_detail.py:_scorecard_length`(holesCompleted=9 短路返回 9,不看 18 位 holePars)+ `_scorecard`(按位置 1..9 建表、按真实洞号查 → 真实洞号 10-18 整列丢)。致「9洞·Par37」、表内合计 ≠ 头部总分。`holesCompleted=18` 早有完整渲染(有测试)。修:按完整 18 洞、真实洞号填已打、未打留空;标签「已打 9 / 18 洞」。iOS 不过滤,纯后端修。
- **1.2 同杆两距离**:`ai_caddie/mobile_live.py:_carry(attack, aggressive=True)=max(median,p90)` → Driver stock=197/attack=221。修:一律 median;激进差异走换杆+瞄准线/风险。altTable(`option.carryM`)/离线种子同步。
- **1.3 选杆**:`LiveHoleComponents.ClubStripView` 只给 3 chip;改全杆下拉 + 默认推荐(round-11 `Self.defaultClub`/`syncSelectedClubToRecommendation` 已铺垫)+ 选完即记。

## 4. 风险与未决(请 Codex 重点审)

1. **Apple Watch 独立 + 自动记杆**:watchOS GPS 精度/电量、后台运动检测可靠性、独立联网(LTE/WiFi vs 必须配 iPhone)、watchOS app 离线事件存储 + 冲突合并。这是最大未知。
2. **三端并发同步**:同一 roundId 多端同时写事件 → 冲突/合并/顺序(现有 events ingest 是否够?需 last-writer/CRDT/序号?)。
3. **Garmin 挥杆统计端点**:平均距离端点是否存在/可 cookie 取(`/club/player.averageDistance`=0,需另探)。
4. **圆模型(7.1)**:动 nine 逻辑面广(实战/复盘/round-11 控件)——这轮做还是单列?
5. **范围**:9 组是否一轮做完(很大),还是 1 组先发版 + 2/3 组单独立项?
6. **自动记杆 UX**:无具体球杆时默认 AI 推荐杆是否会污染球杆距离档案(低可信标注?)。

## 5. 验证现实

- 后端 + 手机/Web UI:本地 `uv run python -m unittest discover -s tests`(930 测试)+ macOS CI(`native-mobile.yml`)+ DesignSnapshotTests 快照,沿用。
- Watch 传感器 / GPS / 自动记杆:**真机 + 球场实测**为主,CI 仅能验非传感器逻辑。

## 6. 决策(已定)+ 执行计划(经 Codex 评审收口)

**Codex 评审结论(homeserver 跑,读真代码)**:方向合理,但现有只是事件**传输**(序列号/去重/重放/ack),**不是权威多端同步**;Watch 纯配套;AutoShot 地基不具备。最大红旗 = 「事件日志=单一真相源」其实没解决;AutoShot 排太前。

**已定决策**:
- **球杆距离**:Garmin 平均距离做**基础**;无 Garmin 的新用户用**预设**(标准业余距离,按杆型/可调);自测(选中杆+GPS,**置信度分层**:手动击球高 / 自动未确认低 / AI默认很低)以后逐步 refine 覆盖。Garmin 挥杆统计端点探测 = 并行 spike,不阻塞。
- **采纳 Codex 分期**(替代「9 组一轮」):
  1. **正确性修复**(1.1 复盘完整18 / 1.2 一杆一距离 / 1.3 选杆下拉默认推荐)← 当前
  2. **同步骨架**(权威每局序列 + 服务端物化 round_state + iOS 重放应用他端事件 + 冲突策略/测试 + 客户端身份)← 多端地基
  3. **Watch 独立「手动」记录器**(选球场/本地日志/直连同步/结束恢复/认证)
  4. **Web 实时查看/编辑**(投影 API 就绪后)
  5. **圆模型迁移**(起始洞/选洞/组合 + 历史数据迁移)
  6. **Watch 手动击球追踪**(确认杆 + GPS 位置 + 算距离;先「击球按钮」非自动)
  7. **AutoShot**(beta/辅助,「疑似一杆,确认?」非静默自动)
  8. **Garmin 挥杆统计端点** spike(并行)
  9. **统计/视觉打磨**(学 GolfLive,数据模型稳后)
- **执行方式**(用户授权):多轮自驱、不打扰;每阶段独立 PR → CI 绿 → 合并 → 部署/TestFlight;仅在真正的产品分叉 / 需真机 / 不可逆时才找用户。

**最欠定义(进各阶段前要先定)**:冲突策略、三端身份/认证、谁能开局、上果岭判定、换洞判定、圆模型数据迁移、最终 round_state 怎么落成历史。
