## 0. 方向裁决

**#218 的暗色 / 绿 / 自绘 topo 语言 = 全表唯一视觉语言,不换方向。** 它是唯一在真 SwiftUI + 真球洞几何上验证过的;近黑底 + 不透明黑药丸是户外阳光下唯一可靠对比;topo 底图已被授权红线 + 渲染实测(0.45s)锁为产品底图。其它所有产物(CSS 记杆稿、CSS 障碍稿、旧手绘机制图、已上线但异色的功能屏)一律**向它靠拢**。

## 1. 唯一视觉系统(规则书)

- **底与面**:页底 = 近黑 `#0A0C0A`(AOD 纯黑);抬升面 = `#1A1D1A`,靠留白 + 字重分层,**不画卡片描边**;次级文字 `rgba(235,235,245,.6)`。
- **强调色只有一个**:球童绿 `#3DDC84`(推荐/选中/主按钮/当前打法档)。金 `#FFD447` = 选中目标/警示/实打修正值;蓝 `#3E9BFF` = 水/果岭前沿;红 `#FF453A` 只在不可逆确认。**任何百分比、± 误差带永不出现**(64%、±18 判死)。
- **成绩色阶(统一 ScoreChip)**:鹰 蓝◎ / 鸟 浅蓝○ / **Par 绿无框** / 柏忌 黄□ / 双柏忌 橙⊡ / 三柏忌 红△ / 更差 紫△——圈/方/三角形状冗余,色盲 + 灰度都能读。成绩环、计分卡、洞详情全用它;废除手表黄 / iOS 粉两套旧色。
- **字**:主数字 = SF Rounded 重磅圆体,**每屏只有一个主数字**(就是长按大字放大的那个);标签全部简中小字,禁英文 token(PinPointer→旗向指引、旗桿→旗杆)。
- **地图**:自绘 topo 战术风,地形色板固定——树 `#2C4A1E` / 粗草 `#436D2E` / 球道 `#5C8F3E` / 果岭 `#7FBF5A` / 沙 `#E8D9A8` / 水 `#3E9BFF`;打球线白色 + 2px 黑描边。**图上一切数字装进不透明黑药丸**(白字、发丝边、零半透明)——进/过、上一杆、测距、前中后,无例外。
- **图标立场**:文字优先(S70 路线);只留旗、GPS 状态几个符号;角落标必带字。
- **成绩环**:18 段窄环只在最外层球道图,用 ScoreChip 色,未打 = 暗灰段;表冠一转进轴就消失。
- **表冠轴指示**:右缘统一一个「轴条」组件(地图 = 沿洞进度、列表 = 滚动条、档位 = 三点),全表同一画法——把操控宪法画在屏上的那根线。

## 2. 每一块归位(含击球检测的归宿)

**五页**(照操控宪法):球局(菜单,最左,吞并 hub)· 球童(表冠三档,只报打法 + 平均杆数)· **球道图(家,居中)** · 计分 · 旗向指引(唯一无轴屏)。球道图把旧 zoom/障碍/测距/果岭/实打**五个独立屏收编为轴位 + 点按对象**:表冠沿洞走 = 全洞 ⇄ 障碍停点 ⇄ 果岭特写,点障碍出进/过黑药丸,点草地测距,点主数字切实打,果岭拖旗。

**击球检测的一致叙事——玩家只见四个触点,其余沉入水下:**
1. **记杆入口**:球道图角落常驻「记杆」带字角标 + 表盘复杂功能同一入口(阶段-1 一键记杆)。它就是「检测」的手动形态;将来 IMU 检测过线,只是让同一个浮层自己弹出来,**入口按钮永不撤**(兜底)。
2. **选杆浮层**:唯一的记杆界面。半屏升起、上方仍露球位→旗新距离,表冠滚杆、推荐居中标「推荐」,点行即记入**当前洞**(不看 GPS),放 8 秒按推荐自动记入标「自动」,下滑 = 误报不记。改杆/补杆复用同一浮层。
3. **上一杆药丸**:图上常挂「上一杆 N 码」(实时,找球用),记杆后刷新。
4. **对账**:计分页表冠预填已记杆数 + 一行「已记 N 杆」来源(「你这洞我数到 X 杆」就长这样,不弹窗);人到下一洞上洞没记分 → 图角浮「记上一洞?」小签。
**水下(不可见)**:IMU 影子采集、GPS 打点滤波、实打高程、离线预取。**击球瞬间永不震动弹窗**(评审红线)。

**判死出清**:独立障碍列表屏(退役)、hub 与菜单双家(并一)、独立大字页(长按替代)、五个地图子屏、手绘机制图(不补,产品里没有「机制」的脸)、∧∨ 钮、自绘返回/×、一切 CSS 稿的正稿地位。**一处纠偏**:全共识计划 Task 1.2 的「表冠=缩放、拖=平移」早于操控宪法 → 以宪法为准:表冠 = 沿洞轴,**地图永不平移**,拖只拖旗。

## 4. 渲染顺序(先立语法,后铺屏)

1. **#17 选杆浮层** —— 全系统唯一新原语、记杆叙事的脸,先定型。
2. **#3 + #7 + 轴条组件** —— 家屏收编障碍态,地图语法就此锁死。
3. **#4 计分**(预填对账)—— 记杆环闭合。
4. **#1 球局并 hub + #18 确认页** —— 导航骨架完工。
5. #2 球童档位。
6. 推入六屏(11/12/14/16 重渲,15 新建)。
7. 开局三步 + #5 旗向。
8. 边缘态 22–26。

每屏验收 = **ImageRenderer 真几何快照,肉眼对图**(macOS native-mobile CI,不用真机)。

## 5. 防碎裂规则

1. **一条渲染流水线**:设计只在 SwiftUI 快照套件里「存在」;HTML/CSS 稿只许探路、不当正稿,**定稿动作 = 快照入库**。
2. **一套组件**:黑药丸 / 主数字 / 轴条 / ScoreChip / 角落标 / 通栏钮 / 加减片——新屏只许拼装;加新原语先改设计系统文档再写码。
3. **四问门 + 清单门**:新屏先答宪法四问(轴?点按?进出?大字?),再答第五问——它是清单上哪个号的态?进不了编号不上表。
4. **禁词进契约测试**:64% / ±18 / PinPointer / 旗桿 由 `tests/test_mobile_contracts.py` 永久封印,英文 token 与繁体一并巡逻。
5. **态优先于屏**:任何新能力默认做成现有页的轴位或点按对象;证明做不成态,才允许新目的地。
