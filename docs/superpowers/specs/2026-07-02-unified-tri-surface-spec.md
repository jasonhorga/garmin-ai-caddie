# AI Caddie 三端统一设计 Spec(手表 / 手机 / 网页)

2026-07-02

## 这份东西是怎么来的

先修了一个小 bug(离线时同一支一号木会显示两个距离),然后请了三个 AI 模型 —— Fable 5、GPT-5.5、Gemini 3.1 Pro —— 各自**独立**把手表、手机、网页三端的设计从头评审一遍,再让它们**互相挑刺**。评审时它们都真看了四套图:我们重做的手表 20 屏、**Garmin Approach S70 用户手册里的打球界面(拿它当对标基准)**、我们手机 App 的现状、我们网页的现状。这份文档就是三家吵完、收敛下来的结论。

需要先说明:下面**有几条结论直接推翻了我这几轮亲手做的东西**(比如恢复被我砍掉的大字、砍掉我费劲做的成绩环)。这很正常,评审就是为了纠偏。

---

## 一、几条铁律(三端都得守)

1. **AI 球童是我们唯一的差异点,而它只说有把握的判断,绝不报假精确的数字。** 它该告诉你的是:用哪支杆、怎么打(稳妥 / 标准 / 进攻)、这一杆大概几杆能上果岭(这个"平均杆数"Garmin 自己也在用)。它**绝不该报"上果岭成功率 64%"这种百分比** —— 我们没有足够干净的数据撑起这种精确度,报了反而显得不专业。

2. 距离一律用**码**;界面一律**简体中文**;不要照搬 Garmin 的英文功能名(比如 PinPointer)。

3. 地图必须是**真实的球洞图**,不能是白底上画几个抽象圆点。

4. 打球这端要**离线优先** —— 球场经常没信号,所以球童要么能在设备本地算,要么开球前就把这个球场的数据全下好。

5. **数据撑不起的功能,先别做。** 没有高程数据就别做坡度补偿("实打"),球杆数据还脏就别显示误差范围(±18 码),没把握就别报成功率。宁可不显示,也不要显示一个让用户将信将疑的数字 —— 因为"信任"是我们唯一的护城河,每个挂着问号的数字都是在训练用户不信我们。

---

## 二、三端各干什么

**手机 + 手表 = 打球的两端**,共用同一套底层(见第三节)。但两者分工不同:

- **手表是打球时的主力**:抬手一眼看距离、看建议、记分,而且**能不带手机、独立打完一整场**。
- **手机是打球时的"控制台"**:屏幕大,用来看大图规划、改记错的分、看两端合并后的真实情况、拍照。**同时,只有手机、没有手表的用户,得能用手机单独打完 18 洞** —— 不能把这类用户晾在一边。
- 换句话说,手机不该去模仿手表那种"抬手一眼"的体验,它该发挥大屏和能编辑的长处。

**网页 = 复盘、备战、看统计、管球包,不打实时的球。**(在网页上看一场"正在进行"的球,以后可以做,但不是现在必须做。)

后端是唯一的"真相源";**打球的时候,手表和手机直接通信**(不用绕后端),后端负责跨设备恢复、以及给网页读数据。

---

## 三、三端共用的那套底层(最重要 —— 不做好这个,界面再统一也白搭)

1. **一个球童大脑,一种输出格式。** 现在三端的球童说的话都不一样:手表说"平均杆数 2.8 + 上果岭 64%",手机给一张"风险 0/1/3"的对比表,网页又写"Safe 94 / Attack 76"。这其实是三套东西,必须合成一个 —— 一个引擎算出结果,三端只是把**同一个结果**用各自的方式画出来。统一往手机那种"序数风险(0/1/3)"靠,别往百分比靠。

2. **一套真实球洞图组件,以手表现在渲染的那套为基准,手机和网页都向它看齐。** 现在手表的图最好(真卫星几何),手机的图是平的绿色多边形、更糙,网页干脆画成白底圆点。方向是"手机网页学手表",别搞反。

3. **一套统一的球局记录格式**(开球、选发球台、切洞、记杆、记推、球道打没打中、罚杆、每一击、改杆、结束)。

4. **多端冲突怎么办(这个要想清楚):** 每一杆、每个距离这种"只增不改"的记录,天然不会打架。真正会打架的只有"某洞打了几杆"这种会被**改写**的数字。规则定成:后改的覆盖先改的;并且**只在手机上**给你看"这个分数被手表 / 手机改过"的历史;**手表上永远不弹冲突提示**,免得打断你打球。

5. 中文用词和单位,三端统一(见第七节 D10)。

---

## 四、手表怎么做

手表是主打球面,对标 Garmin S70。信息分**三层**,别再让"洞图 / 球童 / 放大"这几屏职责重叠:

- **第一层,抬手一眼(也是息屏常显的样子):就是"前沿 / 中 / 后沿到果岭"这三个大数字**,再加一句话建议(比如"推荐三号木,稳妥")。这是 Garmin S70 的主屏(它就是把这三个数字放最大),也是最省电、最该一眼看到的。**这就是我之前砍掉的那个"大字",砍错了,要恢复** —— 它不是和洞视图重复,是被我错放成了一个要滑好几屏才到的页面。
- **第二层,要动手的:真实洞图** + 测距、选点、看障碍、看果岭。
- **第三层,深入看的:球童详细解释、记分、球杆数据、积分卡。**

**自动行为(这是及格线,不是锦上添花):** 走到下一个发球台,自动问你要不要切到下一洞(可以撤销);走动的时候距离要**自动一直刷新**(这本来就是 GPS 测距仪该有的样子,不是额外功能);抬手 / 息屏常显要有大字距离。**自动识别挥杆(AutoShot)先不做** —— Garmin 能做是因为多年积累,我们现在硬上只会一堆记错、然后你花更多功夫去改。

**记分怎么触发(现在完全没设计):** 走到下一个发球台自动弹"上一洞记几杆?",而且**预先填好标准杆或已记的杆数**,你拨一下就行,不用从 0 开始点六下。"球道打没打中"只在四杆、五杆洞问。整个过程随时能跳过、能撤销、能改。

**手上的操作统一成:转表冠 = 缩放 / 微调,拖动 = 平移地图,点 = 确认。** 选点测距时,默认拖地图粗定位,最后几码用表冠沿着你的打球线微调(戴手套、出汗时拖动容易点歪);屏幕上要明确显示现在是哪种模式。

**要砍 / 要改的:**

- **砍掉那圈 18 洞的成绩环。** 表盘那么小,18 根小色条根本看不清,还跟右边的缩放条打架;而且划一下就能看的积分卡里已经有了,主页那个"+2"也够了。
- **删掉球童屏的"上果岭 64%"**(那是成功率),保留"平均杆数 2.8"和稳妥 / 标准 / 进攻。
- **先砍掉"实打 ±8"和球杆的"±18"**(没有数据源:坡度补偿要高程数据、我们没有;球杆数据还脏)。球杆只显示样本够干净的那些。
- 障碍屏要能翻**多个**障碍(转表冠切、标"1/3"),水障碍单独处理(标蓝色不是琥珀色,罚杆含义也不一样)。
- 障碍那条射线要**绑你当前的打球目标线**,不是死死指向果岭中心。
- "上一杆 200"别一直挂在洞视图上 —— 它只在你刚打完那一下有用,改成打完短暂显示、或收进"本洞击球"那屏。
- 补齐各种**异常状态**:GPS 还没定好位 / 漂移了显示什么、离线时球童显示什么、电量怎么省(实时渲真图加 GPS 很耗电,地图层要做得很轻)。
- 菜单按"用得多不多"排序(记分放前面)。
- 把"中"这个距离说清楚:中 = 到旗杆(默认旗在果岭中心);你**拖动旗杆之后,洞视图那个主数字要跟着变**(Garmin 就是跟着变的)。

## 五、手机怎么做

手机是打球时的"控制台",也要能让没手表的人单独打完整场。

- **"当前洞"那屏要改成"地图为主"而不是"卡片为主"。** 现在它全是卡片、根本没地图,而且主距离那个格子还显示"—/0"(打球屏怎么能没有到果岭的距离)。要把真实球洞图做成打球的主界面。
- **把那个洞图换成手表同款的真实球洞图**(现在是平的绿色多边形,比手表还糙 —— 手机屏幕最大、算力最强,图却最糙,不合理)。补上障碍的进 / 过距离、选点测距、果岭前中后 + 拖旗、路线和落点。
- **控制台该干的(手表做不了的都在这):** 任意一洞改分、编辑每一击(补记、删错记、改杆、补罚杆)、**唯一一个能看到"两端合并后真实情况"的地方**(手表连着吗、上次同步是什么时候、哪些分被改过)、看照片。
- **让只有手机的人能单独打完 18 洞**(网页不再实时记分之后,这担子落到手机上,不然这类用户就没人管了)。
- **球童:** 和手表用同一份结果,但手机屏大,先说"这杆怎么打、瞄哪、往哪边失误更安全",再展开理由和备选。
- 手机和手表打球时**直接通信**,切洞、最新一杆秒级同步;其余走后端;同步状态要看得见。
- 一个小 bug:好几处显示"Unknown course"(球场名没解析出来),要修。

## 六、网页怎么做

网页只做复盘、备战、统计、管球包,**不打实时的球**。

- **复盘要补上 2D 落点图。** 手机上已经有了,搬到网页来 —— 大屏最适合看你的球都落在哪、是不是老偏右。现在网页复盘只有一堆数字表格,根本讲不清"这洞为什么打坏"。
- **备战不是给你几行文字,也不是一个工程调试台,而是在大屏上一洞一洞地预览真实球洞 + 试算:** 选球场 → 选发球台 + 你的球包 → 球童一洞一洞给建议(怎么打 + 平均杆数,**不报成功率**)→ 看你以前在这个场的成绩 → 最后生成一份"每洞一句话怎么打"的小抄,缓存到手机 / 手表的备战卡里,打球时直接用。**现在网页把球洞画成白底抽象圆点(最大的屏配了最烂的图,反了),要换成手表那套真实球洞图。** 决策沙盘现在还要你手输"逆风几米每秒"、选击球类型、还露出 Safe 94 / Attack 76(又一处成功率)—— 这些消费者根本不该看到,砍掉。
- **统计已经不错**,只要把颜色和用词跟手机对齐。
- **"补记一局"保留,但去掉浏览器 GPS 实时打球**,改成"赛后手动录入 / 订正"(纸质记分卡事后补录那种),不参与实时打球。
- **设置页要去工程味(这是最扎眼的一屏):** 现在"后端配置"把 OAuth 的 client_id、跳转地址、权限范围、AI 引擎的名字(Gemini、NVIDIA、Anthropic)、甚至一句没翻译的英文,全都露给用户看了 —— 这是把内部架构给用户看。要么只给管理员看,要么删掉。

## 七、十个当时争论的问题,现在的结论 + 为什么

- **D1 大字速览:恢复。** Garmin 的主屏就是这三个大数字,还专门有个"大字模式"。之前砍它,是把"信息一样"错当成"功能一样"了。
- **D2 成功率:全删。** 不管是手表的 64% 还是网页的 Safe94 / Attack76,都是成功率,违反第一条铁律。改用"平均杆数"和"稳妥 / 标准 / 进攻"。
- **D3 假数据(实打、球杆误差):先砍。** 数据源不够(没高程、球杆数据脏)。也别用"低可信度"的小字来糊弄 —— 表太小,大数字一出现用户就当真了。
- **D4 自动行为:** 自动切洞 + 距离自动刷新 + 息屏大字,这三个 v1 必须做;自动识别挥杆先不做。
- **D5 冲突:** 只增不改的记录不会冲突;会冲突的只有每洞成绩,后写覆盖先写,改动历史只在手机显示,手表永不弹。
- **D6 手机角色:** 控制台 + 让纯手机用户能独立打完整场(不是和手表对等的第二个"抬手一眼"的端)。
- **D7 选点交互:** 拖动 + 表冠微调结合;全局统一"转表冠缩放、拖动平移、点确认"。
- **D8 18 洞成绩环:砍。**
- **D9 同步:** 手机和手表之间必须本地秒级直连(两个设备就在同一个人身上,等云端同步 2–5 秒不合理);其余走后端。
- **D10 命名 / 用词:** 全改简体、避开 Garmin 商标名(PinPointer 改成"旗向指引"之类);繁简统一(用"旗杆"不用"旗桿");同一个东西别两个叫法("选点测距"留下、"测量击球"弃掉,"3号木"跟手机对齐、别叫"3木")。

## 八、先做什么、怎么落地

**v1 的底线(缺一不可):**

1. 先把**统一的球童大脑 + 输出格式 + 记录格式 + 冲突规则**定下来 —— 不先做这个,三端会继续各长各的。
2. 做**一套真实球洞图组件**(以手表为基准),手表和手机共用,网页备战也用同一套。
3. 手表达到 Garmin 水准:前中后大字、记分、切洞、距离自动刷新、离线能用、赛后同步、手机手表本地直连。
4. 球童只说有把握的判断(砍掉成功率、坡度补偿、脏球杆误差、自动识别挥杆)。

**要动的清单:** 网页砍实时打球(改补记)、补网页落点图、备战换真实球洞图、设置页只给管理员;手机当前洞改地图为主、换真实球洞图、补"纯手机独立打整场";手表接真数据、砍成绩环、恢复大字、加记分触发和自动行为;三端统一球童格式、用词、配色。

**怎么算做对了:** 手机手表能端到端同步、能离线打完一局、冲突历史只在手机看得到、三端球童说的话一致、界面上**不出现任何百分比 / 成功率**、能完整回放 18 洞。

---

## 九、明确"不做 / 暂不做"

成功率和一切概率;坡度补偿(没高程数据,等有了再说);风(场上难估);自动识别挥杆(v1 先不做,等数据和纠错界面成熟);球杆误差范围(等球杆数据洗干净);挥杆节奏训练(Garmin 有,不是我们的核心);网页实时打球;网页看"正在进行"的局(以后可做,现在不做);果岭等高线。
