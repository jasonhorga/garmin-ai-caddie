## 一、几条铁律(三端都得守)

1. **AI 球童是我们唯一的差异点,只说有把握的判断,绝不报假精确的数字。** 它该说:用哪支杆、怎么打(稳妥 / 标准 / 进攻)、大概几杆上果岭("平均杆数",Garmin 自己也用)。**绝不报"上果岭 64%"这种成功率**。
2. 距离一律用**码**;界面一律**简体中文**;不照搬 Garmin 英文功能名(PinPointer 改"旗向指引")。
3. **地图用真实球洞图**。而且优先用 **Garmin 官方那张精绘俯视图**当底,不再自己画(见附录 A)。
4. 打球端**离线优先**:开局把整场 18 洞的图和数据全下好,全程没信号也能打,回头再同步。
5. **数据撑不起的功能才别做 —— 但要先查清楚数据到底有没有,别想当然:**
   - **坡度补偿(实打)有数据源,做**(几何里 y 轴就是真高程,已实现)。
   - **球杆误差范围(±18)先别显示** —— 击球记录里球杆是脏的(clubId 全是 0),等洗干净再说。
   - **成功率、风:不做**(没数据 / 估不准)。
   - **推杆级果岭等高线:不做**;但**果岭宏观坡向(往哪边倾)可以做**(果岭网格逐顶点有高程)。

## 二、三端各干什么

**手机 + 手表 = 打球的两端**,共用同一套底层(第三节)。

- **手表 = 打球主力**:抬手一眼看距离、看建议、记分,**不带手机也能独立打完整场**。
- **手机 = 打球时的"控制台"**:大屏做规划、改错分、看两端合并后的真实情况、拍照;**同时,只有手机没手表的用户,要能用手机单独打完 18 洞**。手机不模仿手表的"一眼",发挥大屏和能编辑的长处。
- **网页 = 复盘 / 备战 / 统计 / 管球包,不打实时的球。**
- 后端是唯一真相源;打球时手表和手机之间**本地直连**同步。

## 三、三端共用的那套底层(最重要)

1. **一个球童大脑,一种输出格式。** 现在三端说的话不一样(手表"平均杆数 + 64%"、手机"风险 0/1/3 表"、网页"Safe94/Attack76"),必须合成一个引擎、一种结果,三端各自画。统一往"序数风险(0/1/3)+ 平均杆数"靠,零百分比。
2. **一套真实球洞图组件**,以 **Garmin 官方精绘图为底 + 我们的覆盖层**(你点/落点/路线/旗/障碍数字),手表和手机共用、网页备战也用同一套。覆盖层的字形、语义色(绿=推荐、琥珀=沙坑、蓝=前沿/水)三端统一。
3. **一套统一的球局记录格式**,而且**每一击存成独立事件**(带时间戳、GPS 坐标、和一个"归属哪个洞"的字段)。
4. **切洞与冲突,靠"事件 + 可变归属"解决(这是关键):**
   - **每一击归到"你打这击时手表上的当前洞",不看 GPS 落在哪个洞。** 所以你误切了洞、再切回来打,球就记回正确的洞。
   - "洞"只是对一整局的**视图过滤 / 指针**,不是杆的物理归属;改指针不动已记的杆(这跟我们 iOS 端"nine 是视图过滤、改 nine 不丢杆"是同一个模型)。
   - 真会冲突的只有"某洞打了几杆"这种会被改写的数字:后写覆盖先写,改动历史**只在手机显示**,手表永不弹冲突。
5. **同步架构:默认手表 → 手机 → 云**(手表把事件日志用 WatchConnectivity 传给手机,手机上云;这是最省电最可靠的);**没带手机时,手表才借网络直连云**(降级)。核心是一切当"离线日志 + 重连重放",不做实时流。
6. 中文用词、单位三端统一(见第七节 D10)。

## 四、手表怎么做

手表是主打球面,对标 Garmin S70。信息分三层:

- **第一层,抬手一眼(也是息屏常显):前 / 中 / 后果岭三个大数字 + 一句话建议。** Garmin 就是把这三个数字放最大(不是单独一屏,是放在洞视图上做大),另外有个"大字模式"开关能整屏放更大。**我们照这个来:洞视图上前中后做大做显眼 + 一个大字模式开关**,不是单独滑一页。
- **第二层,要动手的:真实洞图** + 测距、选点、看障碍、看果岭。
- **第三层,深入的:球童解释、记分、球杆数据、积分卡。**

**自动行为(及格线):**
- **切洞用"确认式",不静默:** 走到下一台时弹一下 + 震一下:"第 5 洞?[记分] / [还在第 4 洞]",一点即走、误判一点取消。(竞品里 Garmin 静默自动切、关不掉、还改不回来,是最大投诉源 —— 我们绕开它。)
- **走动时距离一直自动刷新**(这是 GPS 测距仪的本分)。
- **抬手 / 息屏常显有大字距离。**
- **自动识别挥杆(AutoShot)先不做实时版** —— 竞品都测不准推杆、都得靠赛后编辑兜底。我们 v1 用**中间方案**:到洞末(或记分时),从你走过的 GPS 轨迹看"你跳了几段(约 210 码、150 码、30 码),是这几杆吗?"让你确认。既解决"忘了当场记",又凑齐了复盘落点图的数据,还没有挥杆误报的问题。

**记分:** 走到下一台自动问"上洞几杆",**预填标准杆或已记的杆**,拨一下就行,不用从 0 点六下;球道打没打中只在四杆五杆洞问;全程可跳过、可撤销、可改。**积分卡点一下某洞 → 直接改那洞的总杆 / 推杆 / 罚杆 → 改完能回洞图、也能回积分卡。**

**手上操作统一:转表冠 = 缩放 / 微调,拖 = 平移,点 = 确认。** 选点测距:默认拖地图粗定,最后几码用表冠沿打球线微调(戴手套 / 出汗防点歪),屏上标明当前模式。

**保留 / 调整:**
- **成绩环:留着,只在最外层洞图显示,一放大就去掉**(负责人拍板)。
- **删球童屏的"上果岭 64%"**(成功率),保留"平均杆数 2.8" + 稳妥 / 标准 / 进攻。
- **"上一杆 XXX 码"一直挂着**(找球用:靠"我现在离上一杆多远"判断往哪找)。这个距离要做**平滑**(原始 GPS 一杆 200 米有 ±5–14 米误差,得把"上一杆位置"用滤波存下来,不能用单次原始定位)。
- 障碍屏能翻**多个**障碍(转表冠切、标"1/3"),**海边球洞的海水障碍要算进来**(现在漏了),水障碍标蓝、罚杆含义不同;障碍射线绑你当前的打球目标线,不死指果岭中心。
- 补**异常状态**:GPS 没定好位 / 漂移、离线球童、电量保护。
- 菜单按用得多不多排(记分放前)。
- "中" = 到旗;拖旗后洞视图主数字跟着变。

**续航(硬约束,已技术核验,详见附录 B):** Series 10/11 **能打完一场但紧**(一场吃 55–70% 电),Ultra 随便打(一场 25%)。**核心结论(纠正了直觉):省电几乎全在屏幕,不在 GPS。**
- **GPS 全程 1Hz 开着、不做占空。** 降"报点频率"(`distanceFilter`)不省 GPS 电 —— 芯片的电是"射频前端 + 相关器一直跟踪卫星"吃的,和读点频率无关;唯一真降 GPS 硬件功耗的旋钮是"精度",但高尔夫每码要准、不能降;真关几分钟才省电但会把距离测歪、不能用。挂着后台 session 时黑屏 GPS 照样在跑,不用"抬手才升频"。
- **省电靠屏幕:垂手熄屏 + 落腕把 UI 刷新降到 10–20 秒一次**(用 `isLuminanceReduced` 判断;生产级 app 靠这个撑 ~12h 连续 GPS)。
- **以手表自身 GPS 为准**(手机常搁球车上,不能依赖手机供 GPS);**赛前设置屏就预热 GPS**,避免脱机时第 1 洞台冷锁定等 1–2 分钟。
- **挂一个 session 保活**(否则黑屏约 2 分钟被系统挂起、丢定位):默认 `HKWorkoutSession`(稳、给活动圆环,但强制开心率、API 关不掉);想不记心率就用 `CLBackgroundActivitySession`(watchOS 10.1+,较新、须真机验证)。
- **提示满电开局。** "到上一杆距离"几乎免费(GPS 本就 1Hz 热着),但"上一杆位置"要滤波存(单点原始 GPS 一杆 200 米有 ±5–14 米误差)。

## 五、手机怎么做

手机是控制台,也要能让没手表的人单独打完整场。

- **"当前洞"改成"地图为主"而不是"卡片为主"**(现在全是卡片、没地图,主距离还显示"—/0")。真实球洞图做成打球主界面。
- **洞图换成和手表同款的真实球洞图**(现在是平的绿多边形,比手表还糙)。坡度补偿(实打)iOS 已经有了、保留;补上障碍进 / 过、选点测距、果岭前中后 + 拖旗。
- **控制台该干的:** 任意洞改分、编辑每一击(补 / 删 / 改杆 / 补罚杆)、**唯一能看到两端合并真实情况的地方**(手表连着吗、上次同步、哪些分被改过)、看照片。
- **纯手机用户能单独打完 18 洞**(网页不实时记分后,这担子在手机)。
- 球童:和手表同一份结果,手机屏大先说"这杆怎么打 / 瞄哪 / 往哪边失误安全"再展开;和手表逐字段对齐(Tee、球道、罚杆)。
- 打球时手机手表本地直连,切洞、最新一杆秒级同步。
- 修"Unknown course"(球场名没解析)。

## 六、网页怎么做

只做复盘 / 备战 / 统计 / 管球包,不打实时球。

- **复盘补 2D 落点图**(把手机的搬过来,大屏最适合看散布 / 偏向)+ 杆序 + 决策 vs 实际对照 + 照片。现在只有数字表,讲不清"这洞为什么打坏"。
- **备战 = 大屏上一洞一洞预览真实球洞 + 试算,不是文本卡、不是工程台:** 选场 → 发球台 + 你的球包 → 球童逐洞给建议(怎么打 + 平均杆数,不报成功率)→ 看你这场往绩 → 生成"每洞一句话怎么打"的小抄,缓存到手机 / 手表备战卡里、打球时直接用。**用 Garmin 官方精绘图预览**(现在画成白底抽象圆点,最大的屏配最烂的图)。**砍掉决策沙盘那些逆风 m/s 手输、击球类型下拉、Safe94/Attack76 成功率。**
- **统计已经不错**,颜色和用词跟手机对齐即可。
- **"补记一局"保留但去掉浏览器 GPS 实时打球**,改成赛后手动录入 / 订正。
- **设置去工程味:** "后端配置"把 OAuth、AI 引擎名、权限范围、英文串全露给用户了 —— 只给管理员看或删掉。

## 七、十个决策(D1–D10)现在的结论

- **D1 大字:** 洞视图上前中后做大做显眼 + 一个大字模式开关(不是单独一页)。
- **D2 成功率:全删所有百分比。**
- **D3 假数据:改判 ——** 坡度补偿(实打)是真数据、**保留**;只把脏球杆的 ± 和推杆级果岭等高线先砍。
- **D4 自动行为:** 距离自动刷新 + 息屏大字 + **确认式切洞** 是 v1;实时自动识别挥杆先不做,用"洞末从 GPS 轨迹确认击球"过渡。
- **D5 冲突:** 每一击归"当前活动洞"(不看 GPS)+ 洞归属可改(切回洞就重挂)+ 成绩后写覆盖先写 + 改动历史只在手机 + 手表永不弹。
- **D6 手机:** 控制台 + 纯手机独立整场(不是对等第二打球面)。
- **D7 选点:** 拖 + 表冠微调结合;全局统一转表冠缩放 / 拖平移 / 点确认。
- **D8 成绩环:保留**(只在最外层洞图,放大去掉)—— 负责人拍板,推翻评审的"砍"。
- **D9 同步:** 默认手表 → 手机 → 云(最省电最可靠);没手机才手表直连云;一切当离线日志 + 重放。
- **D10 命名 / 用词:** 全改简体、避开 Garmin 商标名;繁简统一;同物同名。

## 八、先做什么

**v1 底线:** (1) 统一球童大脑 + 输出格式 + 记录格式 + 冲突规则先定;(2) 真实球洞图组件(Garmin 官方精绘图为底)手表手机共用、网页备战也用;(3) 手表达 Garmin 水准:前中后大字、记分、确认式切洞、距离刷新、离线整场、赛后同步、手机手表直连;(4) 球童只说有把握的判断。

**顺手能捡的便宜(附录 A 的机会,都很容易):** 换 Garmin 官方精绘洞图;解析出每个 Tee 的 Slope / Course Rating(做差点和选 Tee);补回被丢的女士 par / 差点;补上海边洞的海水障碍。

---

## 九、明确"不做 / 暂不做"

成功率和一切概率;风;推杆级果岭等高线;球杆误差范围(等球杆数据洗干净);实时自动识别挥杆(v1 用轨迹确认过渡);网页实时打球;网页看"正在进行"的局(以后可做);挥杆节奏训练。

## 附录 A:Garmin 球场数据里的发现(Fable 深挖,已代码验证)

- **坡度补偿(实打)是真的:** 几何网格第二维 y 就是真实高程(山地场实测 tee→果岭落差 −31 到 +27 码,足够改选杆);`elevation.py` 早已实现、结果进了 iOS。所以实打**保留**。
- **官方精绘洞图:** 每洞有一张 Garmin 官方渲染的俯视图(1242×1920,带树影 / 球道条纹 / 水域,比我们代码自绘漂亮一档),匿名可下、每张 ~130KB、和我们的几何**像素级对齐**。~~拿它当洞图底图~~ **【2026-07-03 已推翻,见附录 C:签名 URL ≠ 商用授权,官方 raster 只作内部质检对齐;产品底图改用我们自绘的 topo 风(已证渲染 0.45s、能渲得一样好)。】**
- **下载了没用上的数据:** 每个 Tee 的 **Slope / Course Rating**(难度 / 坡度值,做差点、做选 Tee 的地基)、九洞小计 par、**女士 par / 差点(代码只取了男士、丢了女士)**、海边洞的 **Ocean / Beach 海水障碍**(现在只认 Lake+Bunker)。
- **"3D 的图":** prodgeometry 包就是 Garmin app 里 3D 飞览的整套资产(碰撞地形、法线贴图、带朝向和树种的树);还有一份没碰过的 DEM 高程文件(第二个高程源)。
- 果岭网格逐顶点有高程(单果岭高差可查)→ 可做**果岭宏观坡向箭头**,做不了推杆级微等高线。

## 附录 B:续航与竞品(Fable 研究,带官方数据 + 竞品出处)

- **续航:** Series 10/11 一场吃 55–70% 电(能打完但紧),Ultra 一场 25%(连打 3–4 场)。**技术核验纠正了一个直觉误区:降 GPS 报点频率几乎不省电**(`distanceFilter` 只是软件回调过滤器,GPS 芯片的电由"持续跟踪卫星"主导;唯一真降硬件功耗的是 `desiredAccuracy` 精度档,高尔夫不能降;真省电只能长关几分钟、但会把测距测歪)。**能省的电几乎全在屏幕**:垂手熄屏 + 落腕把 UI 刷新降到 10–20s(`isLuminanceReduced`),生产级 app 靠这个撑 ~12h 连续 GPS。**GPS 全程 1Hz 热着别占空**;挂 session 保活(workout 强制 HR 且 API 关不掉,或 `CLBackgroundActivitySession` 无 HR 但需 watchOS 10.1+ 真机验证);**以手表自身 GPS 为准**(手机常在车上)、赛前设置屏预热避免冷锁定;满电开局。别把"抬手"当 GPS 硬触发(watchOS 无抬手 API、检测 ~3s 且抖)。
- **竞品:** 没人能从手腕稳测推杆(都靠赛后编辑兜底);**只有 Garmin 真离线**(表里预装图、表上开局),所有手机 App 竞品都要联网"开局" ← 这是我们的最大差异化空档;**没人解决误切洞**(证据都支持"确认式切洞 + 易撤销")。
- **同步:** 手表 → 手机 → 云最省电最可靠(WatchConnectivity 保证最终送达、按序);手表直连云有已知坑(手机在旁但离线时请求会失败),只做无手机降级。

## 附录 C:渲染与数据架构 + Web/iOS 视觉方向(2026-07-03 三模型对抗结论)

三模型(Fable/Claude · GPT-5.5/Codex · Gemini 3.1 Pro)就负责人 7 点反馈各自独立深想 + 交叉对抗后收敛。色阶 hex 与形状见设计系统 `2026-07-03-design-system.md`。

### C.0 关键前提纠正:自绘渲染不慢(这条改写了整个问题)
生产 `hole_render.render_hole` 真机实测 **0.45s**(SS=2)。此前以为"要 7.5s"——那 7.5s 里 **6.7s 是一段可删的幼稚水深滤波**(超采样大画布上跑 6×MinFilter 秩滤波),换 numpy 距离变换只要几十毫秒;富渲染(hillshade + 树 + 水 + 沙)优化后 ~0.8–1.2s@SS3 / ~0.4s@SS2。**所以"因为渲染慢,必须挪到端上渲 / 上矢量瓦片"这条推理,前提就是错的。** 三家一致:速度不是约束。

### C.1 渲染 / 数据架构(核心,2 家主张 vs 1 家异议)
**主张(Fable + GPT-5.5,采纳为主线):**
- **服务器 = 唯一真源 + 唯一位图渲染器。** 全量镜像我们自己的 **CoursePack**(从 prodgeometry 转出的 LOD 网格 + 障碍多边形 + 果岭坡向 + 高程栅格 + tree instances)+ release protobuf 入库;**绝不存解码后的 JSON**(那会把 ~100GB 膨胀到 ~600GB)。
- **服务器预渲成品位图底图,两套风格**(light 复盘 / dark 打球),多分辨率;**iPhone 只渲交互覆盖层**(GPS / 落点 / 目标线 / 球杆环 / 球童 / pin / 杆序);**Apple Watch 永不渲 3D、永不解网格**,只拿手表尺寸成品位图 + 极少 native overlay;**Web 首屏也用服务器预渲图秒开**,大屏交互再叠。
- **位图 vs 矢量分工**:底图必须位图(地形光影 / 树影 / 水面渐变 / 沙不是纯矢量能便宜表达);**放大后的锐利全靠矢量叠加层**(距离环 / 码数标签 / 落点椭圆 / 球位——无损缩放永远清晰)。不追求"全矢量无损",不需要 gigapixel 底图。
- **存储非约束**:官方 raster ~130KB/洞、prodgeometry zip ~193KB/洞;几万球场全量 raster+zip 也就 ~100–175GB(对象存储月成本个位数美元;Cloudflare R2 $0.015/GB-月、出网免费)。矛盾不在存储,在新鲜度 + 客户端体验。
- **离线包**:用户排定/选场那刻后台预取整场——最小打球包 ~5–15MB(元数据 + 18 洞 overview + 障碍索引 + 果岭/pin + 球包),高清包 30–100MB(多级瓦片 + 几何 LOD,tee time 前 / Wi-Fi / 充电时下)。手表只同步当前洞 + 下一洞的小底图 + 距离。**开局前整场在本地 → 第一洞瞬时、全程离线**;纯手机整场必须能离线打完(计分/落点/球童本地兜底,赛后再同步)。
- **签名过期**:客户端永远不碰上游签名 URL;服务器 resolver 需要时重新取授权 URL;我们自己的对象 key immutable(`course/{id}/data/{hash}/style/{s}/hole/{n}/z/{z}.avif`),版本只增不覆盖,正在打球的用户用旧 manifest、结束再提示更新。
- **热门全量预渲、长尾按需补齐但不阻塞开局**(冷门场先给 overview,用户打开后后台补高清)。

**异议(Gemini):** 客户端跑 3D——iOS 用 Metal/SceneKit 实时解几何(<2MB)渲 3D,手表拿 iOS 降维展平的 2D 矢量路径;按需拉取 + CDN 长缓存;丢弃官方 raster。理由:无损缩放 + 动态光照 + 不浪费服务器算力("服务端渲图是耻辱")。**GPT-5.5 直接驳**:手表算力解不了 Draco + hillshade、耗电/发热/延迟不可接受;手机也不该把"开局体验"押在解网格 + 3D 上。→ **折中采纳**:手表 / 手机打球走「位图底 + 矢量叠加」;**Web 备战大屏才用 WebGL 3D**(有算力、无手表约束,拖着看整洞 + 与 iOS 同源 Draco 数据,是客户端 3D 唯一合理的地方)。

**⚠️ 授权红线(GPT-5.5 提,别人都漏):** Garmin 官方 raster "匿名可下 + 签名会过期" **≠ 商用授权**;签名 URL 不能当产品资产 URL、更不能暴露给客户端。**结论:产品洞图底图用我们自绘(topo 风,已证能渲得一样好、能把产品覆盖层烘进去、无签名过期、可离线),官方 raster 只留作内部质检 / 像素对齐**——除非拿到授权。这**推翻**了附录 A 与 data-to-features 里"以官方 raster 为底图"的旧结论。

### C.2 洞图渲染风格(Q2,三家一致:topo 战术风,不抄 Garmin,保留 3D 阴影)
- **方向 A(主推)地形等高线 / Editorial Topo**:真高程 hillshade + 环境光遮蔽当主角,球道/果岭去饱和哑光平涂,叠细等高线(每 1–2m,从同一高度栅格抽、成本≈0),树=小而统一的深色点 + 短投影,水=墨蓝 + 单条岸高光。像高级码数手册,数据诚实的识别度。
- **方向 B 暗色战术图**:炭灰 rough / 球道略亮 / 障碍微光,贴"打球=暗色"。
- **不走**:Terrain.webp 逐像素贴图 / 照片级(要补 Draco UV,投入大且更像抄 Garmin)。

### C.3 Web 整体重做(Q3,三家一致:桌面工作台,不是放大的手机、不是营销看板)
- **导航**:复盘 / 备战 / 统计 / 球包(+ 设置);顶栏球员 / 时间范围 / 球场搜索 / 同步状态 / 导出。Web 不打实时局。IDE 式布局(左窄导航 · 中左大视窗 · 右控制面板)。
- **备战(发挥大屏)**:选场 → 中间大画布真几何逐洞(WebGL 3D 可交互)+ 左栏洞列表(par/长度)+ 右栏球童试算(点球道任意点 → carry / 障碍 / 实打 ±)→ 导出 **crib sheet**(可打印 9/18 单页)并同步到 iOS/手表。
- **复盘**:球局列表 → 单局落点图(真实落点投到洞图)+ 杆序 timeline + 决策 vs 实际 diff + 同场多轮对比。
- **统计**:strokes-gained 总览 + 开球/攻果岭/短杆/推杆 + dispersion / miss pattern / 距离分布 / 趋势,可筛选对比;高信息密度,不做幼稚饼图。
- **球包**:球杆 + carry/total/P50/P80 + dispersion 椭圆 + gapping chart + 校准(与 iOS 同一份 club profile)。

### C.4 iOS 视觉重做(Q4,三家一致:去色块、语义色、iOS 原生克制)
- 抛弃大面积浅绿/灰绿背景,严格用 systemBackground(浅=白 / 深=纯黑或极深灰);**品牌绿只当强调色**(Par 色、主按钮、关键状态),不做大面积填充。
- **无边界数据展示**:统计/分数去掉包裹卡片边框,靠字重(SF Pro Heavy/Medium 对比)+ 留白划层级;to-par 颜色只落在数字 chip,不铺整卡背景。
- 悬浮面板(球童浮层)用系统 Blur 材质透出底部洞图;全面深色模式(打球场景 = 暗面)。

### C.5 色阶 + 色盲(Q5)
明确 hex(打球暗面 + 复盘亮面双值)+ 圈/方/三角形状冗余见 `2026-07-03-design-system.md` §一。要点:色相走赤橙黄绿青蓝紫、**Par 绿**;红绿色盲靠**数字 + 圈/方形状 + 单调明度**三重冗余,不靠色相。
