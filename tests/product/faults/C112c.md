# C112c navigation callback faults

J5.2 requires Back to reach the home with its resumable active-round card. J5.10 page freezing
must preserve the displayed hole's inputs and the live cursor. These mutations restore the
render-time decisions that can lag a synchronous first-stroke start.

All mutant targets are native unit tests in `ProductLiveHolePageTests`. Faults 01–04 cover the
shortcut course route's theoretical stale snapshots; they do not explain or repair the observed
J5.2 new-round UI failure, whose `.start` route is replaced with a single `.hole(1)`.
The original fixture mounts
the real `RoundHomeView` with `[.startCourse(...), .hole(4)]` and a real `LiveRoundAppModel` /
isolated `OfflineStore`. A DEBUG-only probe retains the exact start and dismiss closures passed
to `CurrentHoleView` and the mounted home's path binding. No navigation rule is recreated by the
test. `withPrepSession` stops model background downloads before exercising local navigation.

The unstarted-dismissal and different-active-round cases protect against unconditional path
collapse and outgoing-page cursor writes. Existing hosted N=20 body-count, callback freshness,
selection, score-edit and drag-refresh tests remain unchanged.

The new observed fixture awaits main-actor work with `Task.yield` / bounded asynchronous sleeps.
The shortcut fixture uses the same wait; the old synchronous body-count harness is unchanged.
The existing `ProductPhoneUITests/test_j5_2_home_active_card_replaces_new_round_and_can_resume`
continues to exercise actual course selection, recording a shot, closing its club sheet, tapping
Back, the home hero, and resume. It additionally requires exactly one accessible Back button.
The unit test calls retained production actions and does not synthesize UIKit taps or present a
club sheet; the UI journey covers those integration steps.

DEBUG evidence is in the existing `debug-pager-trace` attachment: `page body` is throttled to one
record per hole per second, except selection changes are always recorded. `back tap` identifies
the course hole, selected flag and pager page. `back owner before/after` surrounds the owner
callback; `back home path before/after` records its synchronous binding write; every observed
path change records both arrays. Standalone destinations (or a reverted owner callback) log
`back dismiss before/after` around the actual environment dismissal. A tap on selected=false
identifies wrong-page activation; a dismiss pair with no path change identifies an ineffective
environment action; no tap event points to hit testing rather than path reconciliation.

The earlier failure trace contained no post-Back path event and showed the selected first hole
before the first stroke. It cannot establish a later selection mismatch, a duplicate hit, or the
precise SwiftUI environment lifetime. Native evidence is still required to distinguish them.

Local Linux validation checks patch applicability and registered targets only. Native compilation,
the green unit run and killed-mutant results require the macOS CI runner; they have not been
claimed as local evidence.
