# C163 故障清单（J4.2）

所有条目测运行行为，不读取产品源码。`test_c163` 的 HTTP 用例保留真实 main → mobile
builder → map_startup → vector cache 接线，仅替换事实载荷、外部 IO 和 CPU 边界的确定性结果。
并发检查使用 Event 扣住 gate/compute；历史重入用独立解释器的 5 秒超时边界。

| mutant | 目标行为与判红 |
|---|---|
| 01-vector-back-in-api | cache 冷命中必须提交共享 CPU 池，API seed spy 不被直接调用 |
| 02-signature-never-compared | old→new 签名必须启动 warm |
| 03-403-no-backoff | 真正去掉 release 闸；首次 403 后 rescan 不得立刻再下载（替换旧 pending→failed mutant） |
| 04-ladder-reentry | 不传事实 ladder 会在真实 single-flight/profile/frame/prep 链中超时 |
| 05-startup-skips-process-lane | HTTP 后台包必须沿真实 startup 接线到进程边界；复审 Ma |
| 06-startup-skips-background-gate | 后台被扣在闸外，前台同洞可计算且只计算一次；复审 Mb |
| 07-route-never-background | HTTP 预下载无活跃租约必须走进程边界；复审 Mc |
| 08-ignore-forbidden-retry-after | 只忽略 retryAfter、保留次数上限，rescan 提前重下即红；复审 Md |
| 09-history-drops-empty-ladder | ladder=None 在事实 frame 被规整成 []；删掉会重入超时；复审 Me 的保护已移到所有入口共用的 frame，profile 的冗余 [] 已删除 |
| 10-warm-acknowledges-later-change | 扣住第一次 warm，第二次文件变化必须再 warm，不能完成时吞掉最新签名 |
| 11-cpu-children-remain-resident | 停止启动 idle timer 后，完成的池不会 shutdown，Event 超时判红 |
| 12-new-map-round-is-background | 新局 map_only 与普通包均在登记租约后走前台，进程 spy 不能被调用 |
| 13-background-reserves-geometry-worker | 两个后台单元等闸/计算时，共享池仍能立即完成前台 priority-hole prepare |

实际结果与性能对比交项目台回话；`tests/perf/c163_concurrency.py` 只使用生成的合成事实，
调用真实生产计算，分别输出 history 冷构建、HTTP /tees 和 vector 墙钟，不设 CI 性能阈值。
