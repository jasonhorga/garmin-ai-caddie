# C198 故障清单（发布门 G6：只有当前发布容器 `on-failure:3`）

| 行为 | mutant | 测试为何走到该行 |
|---|---|---|
| 新版本以 `--restart no` 起 | 01-new-release-runs-on-failure | 假 curl 记下每次健康检查时在服务的容器的策略，新版本必须一直是 `no` |
| 发布记录写入后才改 `on-failure:3` | 02-marked-live-before-record | 假 docker update 记下当时发布记录里的 revision，必须已经是新版本 |
| 换下的旧容器改 `no` | 03-switch-keeps-replaced-on-failure | 旧容器起始为 `on-failure:3`，deploy 后只有新版本是 on-failure |
| 失败回滚恢复的容器改回 `on-failure:3` | 04-restored-release-not-marked-live | deploy 新版本不健康、rollback 目标不健康、重跑校验失败三种恢复 |
| rollback 成功后目标是 `on-failure:3` | 05-rollback-target-not-marked-live | rollback 到 OLD，另有一个 on-failure 的多余旧容器 |
| rollback 换下的容器改 `no` | 06-rollback-keeps-replaced-on-failure | 同上，NEW 被换下后必须是 `no` |
| normalize 按不变式校正，不是全改 `no` | 07-normalize-all-no | `up` 时 Docker 已拉起当前容器，不 start，只校正策略 |
| normalize 校正所有多余的 release 容器，不碰别的项目 | 08-normalize-skips-other-releases | 多余旧 release 和别的项目容器都是 on-failure，rollback（幂等分支）后 |
| `up` 当前容器在跑时也校正 | 09-up-running-release-not-normalized | 同 07 |
| `up` 启动已停当前容器时校正 | 10-up-started-release-not-normalized | 库先停、当前容器重试耗尽已停，`up` 等库后再 start |
| 入口等库就绪再迁移 | 11-entrypoint-skips-database-wait | 假 pg_isready 一直不就绪，uv 不得被调用 |
| 入口等库有上限（12 次×5 s） | 12-entrypoint-database-wait-unbounded | 假 sleep 记录间隔，必须 12 次探测、11 次 5 s |
