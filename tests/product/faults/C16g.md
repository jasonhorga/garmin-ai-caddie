## Rerun

For example, from the repository root:

```sh
git apply --check tests/product/faults/C16g/9.1-average.patch
git apply tests/product/faults/C16g/9.1-average.patch
(cd web_v2 && heavy-lock npx playwright test e2e/product --project=desktop-chromium --grep '9.1 scores-performance')
git apply -R tests/product/faults/C16g/9.1-average.patch
```

Use the table's exact row for 9.2–9.4. For 9.5 use
`--grep j9_5_review_has_single_round_share_entry`. A healthy browser baseline
is required first. A kill must fail the named product assertion on the mutant
and pass its baseline. Browser launch failures, fixture setup failures and
unrelated assertions do not count as semantic kills.

## Measured boundary

The project console ran the corrected suite with installed
`chromium_headless_shell-1234`, selected through an external config's
`launchOptions.executablePath`: 26 passed and four failed as expected (all 30
cases accounted for). It also ran the five patches: five target tests turned
red out of five. This is four semantic regression mutations plus the 9.5
review-entry prerequisite mutation; the latter is not a share-authorization
kill. All five patches also pass `git apply --check`.

These browser results were supplied by the project console. The execution
sandbox still has no visible browser executable; local verification covers
collection, lint and patch applicability. For local browser reruns, follow the
external-config instructions in `web_v2/e2e/product/README.md`; do not run
`playwright install`.

The real round-share implementation is absent. Consequently there is no
share token, anonymous view or per-round authorization code to mutate here.
The 9.5 patch only checks that a setup regression is not hidden by the late
known-red annotation. It does not fulfill a future semantic share mutation.
After sharing exists, add a mutation that exposes another round or an edit
control and extend the primary 9.5 test to kill it. See the known-red document
for the same limitation on the share-view row of 9.4.
